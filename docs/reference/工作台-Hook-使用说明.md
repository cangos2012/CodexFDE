# 在事项中准备 Stop Hook

入口：工作台首页 → 事项与决策 → 选择已有执行结果的事项 → 本轮成果 → **Stop Hook · 结束前自动检查**。

先取得本事项的隔离候选，状态为待审核或返工，并确认项目质量命令。点击“准备候选 Hook”后，工作台会在运行目录的 `hook-packages/` 下生成一份新的待审包，保留准备者、事项、任务、候选绝对路径、质量命令及文件指纹。重复准备保留旧包，不覆盖原记录。

FlowERP 保持独立仓库。Hook 使用本事项已确认的 FlowERP 质量命令，在 FlowERP 隔离候选目录执行；不会退回 CodexFDE 的默认检查。处理器通过工作台解释器复用 `CandidateProjectEval`，客户仓库无需安装工作台包。工作台及其运行目录必须仍可访问；移动目录后重新准备。

1. 打开面板显示的待审目录，检查 `binding.json`、`hooks.json` 与 `quality_gate.py`。配置中的 Windows 命令使用 PowerShell EncodedCommand 处理路径引号，实际命令可从处理器和绑定文件核对。
2. 在候选中备份已有 Hook 文件，将待审 `hooks.json` 的 Stop 规则合并到候选 `.codex/hooks.json`，将处理器放到 `.codex/hooks/quality_gate.py`。已有同名处理器时先审查冲突，不直接覆盖。
3. 在该候选启动 Codex，使用 `/hooks` 审查并信任当前定义。网页只核对安装文件是否匹配，不读取或修改 Codex 信任记录。
4. 触发一次正常结束，回到本事项查看调用记录。自动刷新会展示结果与报告是否仍对应当前候选；需要结合 Codex 会话记录确认真实宿主事件。手工输入 Stop JSON 也会留下记录，因此不能仅凭记录存在认定自动触发成功。
5. 若检查失败，修复同一候选后显式点击“重新运行候选检查”，再由实际审核者验收。Hook 通过不自动接受任务；重入只显示跳过，不产生通过报告。

内部检查超时为 100 秒，外层 Hook 时限为 120 秒。运行复用工作台已有的受控进程执行器，超时、命令不可用、报告缺失、空用例、退出码与结论矛盾均保持未验证并返回阻断。报告和原始进程输出保存在运行目录的 `project-reports/`，Hook 调用记录保存在对应待审包的 `run-*.json`。

这是可复用的本地检查连接能力。真实宿主触发、FlowERP 业务通过和具名人审仍须分别留证。

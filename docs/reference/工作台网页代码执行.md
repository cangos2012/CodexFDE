# 工作台网页代码执行

普通启动下，“提交并复验”只检查已有候选。需要从网页执行本讲课程任务时，在仓库虚拟环境中启动：

**Windows（PowerShell）：**

```powershell
.venv/Scripts/python.exe -X utf8 -m workbench.cli serve-workbench --enable-code-execution
```

**macOS（zsh）：**

```zsh
.venv/bin/python -X utf8 -m workbench.cli serve-workbench --enable-code-execution
```

这个入口只允许绑定本机地址。需要本机可用的 Codex CLI 与课程起始基线；打开功能不等于授权某次执行。

1. 点击“新建任务”，选择“让 Codex 实现”，填写署名、选择讲次，再点击“查看范围与执行方案”。这一步只检查条件并准备方案，不运行代码修改。
2. 阅读方案中的具体任务与验收要求，展开核对允许修改的文件、检查用例和起始版本。不符合预期就返回调整。
3. 明确授权后，工作台建立隔离副本，先运行检查；没有起始失败就停止，避免把已有成果算作新实现。
4. Codex 在隔离副本中修改。工作台核对文件差异，再复验。通过后等待人审，不自动合入源仓库。

L04～L14 执行本讲固定合同。普通复验里的“现场需求”不会替换代码执行合同。L15/L16 则必须绑定本次具体需求：可以从“事项与决策”中已决定进入交付的事项进入，也可以粘贴六段式 Spec；两种来源不能同时使用。另需填写本次新增检查和需求起始基线。工作台会冻结需求内容并记录指纹，不把一句自由描述直接当作完整执行合同。

### L15、L16：先取得新增检查与起始基线

填写页面前，先在课程隔离检查候选中保存本人确认的 Spec，只增加针对新需求的检查。运行既有检查应通过，新增检查应因真实能力缺口失败；环境错误和零用例先处理。保存检查文件的实际 Git 提交后，核对该提交在控制仓库可解析，并位于本讲起始标签之后。

按 [L15 手册第 5.1～5.3 节](../courses/L15/实践操作手册.md#51-准备可保存提交的检查候选)或 [L16 的新增需求起始检查](../courses/L16/实践操作手册.md#new-requirement-start)取得实际用例名、Spec 路径和检查提交，再填入页面。页面授权后会创建正式执行候选；后续复验使用返回的候选，不继续在准备检查的旧目录中验收。未取得这些输入时，停在准备阶段并保留原因。

## 入口不可用时

“让 Codex 实现”不可选时，展开“如何开启网页执行”。未开启服务开关与 CLI 不可用分别提示；启用开关不代表基线、登录或本讲前置条件已经验证。准备方案时仍会检查讲次条件，实际执行时仍可能遇到登录或运行错误，并保留失败记录。

若 8001 已运行，先核对没有正在执行的任务，再在原终端结束服务，用上面的启动方式重启。保留原有 `--runtime-dir`、`--port` 和 `--erp-url` 参数；不能换一个空目录后把旧任务消失误认为数据被删除。只刷新网页不能更新运行中的 Python 服务。不要为了启用按钮直接终止正在工作的 Codex 子进程。

同一方案重复授权不会重复启动；未授权方案15分钟过期。方案本身保存在当前服务内存中，服务重启后需重新查看；已经创建的任务与授权事件保存在工作台数据库中。同一运行目录只允许一个工作台服务。重启后，已授权但尚未完成红绿差分的网页代码任务进入待人工核对，不自动重复执行；已经通过差分的待审任务保留人审状态。该状态隔离已用维护者任务夹具和真实进程终止验证，尚未验证真实Codex残留子进程处置。遇到中断先核对任务、隔离副本及残留进程，不要直接重复授权。

署名用于记录责任，不是登录身份认证。此入口尚未完成真实 Codex 浏览器全程交付验收；接口夹具测试、方案截图不能替代一次真实代码交付，也不能替代学生学习证据。

L04 网页执行方案还要求填写已接受的 `WB-L04-BOOTSTRAP` 任务编号，并展示独立复验人与接受人。必须先由学生直接监督 Codex 完成 V0，再由非构建者独立复验、签收；不能让库存导出的一次绿灯替代工作台验收。操作步骤见 [L04 工作台独立验收衔接](../courses/L04/实践操作手册.md)。这项检查验证职责记录，不提供身份认证或真实学习证据认证。

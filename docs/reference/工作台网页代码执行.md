# 工作台网页代码执行

工作台首页上方的“新建交付事项”用于日常需求：从“事项与决策”记录问题，再调研、确认方案、授权执行和验收。交付页的“课程任务与复验”则用于按讲次跟跑，检查或实现课程任务。先按本次目标选择入口：

| 本次要做什么 | 使用入口 | 预期结果 |
|---|---|---|
| 解决一个真实问题，需求尚待澄清 | 上方“新建交付事项” | 建立事项，在同一工作台内推进决定与交付。 |
| 检查所选讲次的已有课程成果 | “课程任务与复验”→“运行本讲课程复验” | 先核对目录与固定检查，再创建复验记录并保留报告；不会修改代码。 |
| 让 Codex 完成本讲课程任务 | “课程任务与复验”→“让 Codex 实现本讲任务” | 核对具体方案后授权，在隔离候选中实现并复验。 |

复验备注只用于说明本次检查背景，不会生成新用例，也不会改变所选讲次的验收范围。任意新需求先从“事项与决策”开始；L15/L16 的课程实现入口也必须绑定已确认的具体需求合同。

## 复验已有课程成果

普通启动即可使用课程复验，不需要开启网页代码执行。操作按以下顺序完成：

1. 填写署名，进入“课程任务与复验”，选择“运行本讲课程复验”和本次讲次。
2. 核对页面展示的工作台源目录、FlowERP 项目与源目录、固定自动检查和检查边界。这些信息来自当前运行的工作台服务；自定义运行目录中的项目登记不能被另一个默认数据库替代。只有一个合适的 FlowERP 项目时自动选中，多个项目时须选择本次要检查的项目。
3. 若页面提示项目未登记、项目目录不正确、项目虚拟环境缺失或固定用例不可用，先按诊断修复配置，再刷新核对。条件未满足时不会创建复验任务，避免把环境故障当作学生成果失败。
4. 条件就绪后，可填写备注或已有业务对象编号，再提交复验。业务对象编号只保留对账线索，不会创建、审批或入库采购单。
5. 打开复验记录，逐项核对报告中的检查名称、通过或失败、原因和退出结果。自动检查通过后，仍须按本讲手册补齐运行证据与具名验收。

例如 L12 自动复验包含 `purchase_requires_approval` 和 `receiving_is_idempotent`，检查采购未经审批不得入库、同一入库幂等键只生效一次。它不覆盖完整 Graph Trace、状态保存与恢复、审核打回或具名人审证据；这些仍按 [L12 实践操作手册](../courses/L12/实践操作手册.md)完成。两项自动检查通过，只能说明这两项规则通过，不能单独判定 L12 学习达成。

若已有任务显示“阻断失败”，先看分项原因。环境原因先修项目登记、目录、解释器或用例配置；业务断言失败则在对应项目中修复实现，并保留失败证据。修复可通过日常事项组织，或在符合本讲起点时使用课程实现入口。修复后在原任务中“再跑复验”，继续保留同一任务的前后结果；这个按钮只运行检查，不会自动修改代码。反复新建复验记录不会修复相同故障。

## 授权 Codex 实现课程任务

需要从网页执行本讲课程任务时，在仓库虚拟环境中启动：

**Windows（PowerShell）：**

```powershell
.venv/Scripts/python.exe -X utf8 -m workbench.cli serve-workbench --enable-code-execution
```

**macOS（zsh）：**

```zsh
.venv/bin/python -X utf8 -m workbench.cli serve-workbench --enable-code-execution
```

这个入口只允许绑定本机地址。需要本机可用的 Codex CLI 与课程起始基线；打开功能不等于授权某次执行。

1. 填写署名，进入“课程任务与复验”，选择“让 Codex 实现本讲任务”和本次讲次，再点击“查看范围与执行方案”。这一步只检查条件并准备方案，不运行代码修改。
2. 阅读方案中的具体任务与验收要求，展开核对允许修改的文件、检查用例和起始版本。不符合预期就返回调整。
3. 明确授权后，工作台建立隔离副本，先运行检查；没有起始失败就停止，避免把已有成果算作新实现。
4. Codex 在隔离副本中修改。工作台核对文件差异，再复验。通过后等待人审，不自动合入源仓库。

L04～L14 执行本讲固定合同，复验备注不会替换代码执行合同。L15/L16 则必须绑定本次具体需求：可以从“事项与决策”中已决定进入交付的事项进入，也可以粘贴六段式 Spec；两种来源不能同时使用。另需填写本次新增检查和需求起始基线。工作台会冻结需求内容并记录指纹，不把一句自由描述直接当作完整执行合同。

### L15、L16：先取得新增检查与起始基线

填写页面前，先在课程隔离检查候选中保存本人确认的 Spec，只增加针对新需求的检查。运行既有检查应通过，新增检查应因真实能力缺口失败；环境错误和零用例先处理。保存检查文件的实际 Git 提交后，核对该提交在控制仓库可解析，并位于本讲起始标签之后。

按 [L15 手册第 5.1～5.3 节](../courses/L15/实践操作手册.md#51-准备可保存提交的检查候选)或 [L16 的新增需求起始检查](../courses/L16/实践操作手册.md#new-requirement-start)取得实际用例名、Spec 路径和检查提交，再填入页面。页面授权后会创建正式执行候选；后续复验使用返回的候选，不继续在准备检查的旧目录中验收。未取得这些输入时，停在准备阶段并保留原因。

## 入口不可用时

“让 Codex 实现本讲任务”不可选时，展开“如何开启网页执行”。未开启服务开关与 CLI 不可用分别提示；启用开关不代表基线、登录或本讲前置条件已经验证。准备方案时仍会检查讲次条件，实际执行时仍可能遇到登录或运行错误，并保留失败记录。

若 8001 已运行，先核对没有正在执行的任务，再在原终端结束服务，用上面的启动方式重启。保留原有 `--runtime-dir`、`--port` 和 `--erp-url` 参数；不能换一个空目录后把旧任务消失误认为数据被删除。只刷新网页不能更新运行中的 Python 服务。不要为了启用按钮直接终止正在工作的 Codex 子进程。

同一方案重复授权不会重复启动；未授权方案15分钟过期。方案本身保存在当前服务内存中，服务重启后需重新查看；已经创建的任务与授权事件保存在工作台数据库中。同一运行目录只允许一个工作台服务。重启后，已授权但尚未完成红绿差分的网页代码任务进入待人工核对，不自动重复执行；已经通过差分的待审任务保留人审状态。该状态隔离已用维护者任务夹具和真实进程终止验证，尚未验证真实Codex残留子进程处置。遇到中断先核对任务、隔离副本及残留进程，不要直接重复授权。

署名用于记录责任，不是登录身份认证。此入口尚未完成真实 Codex 浏览器全程交付验收；接口夹具测试、方案截图不能替代一次真实代码交付，也不能替代学生学习证据。

## L04 的前置工作台验收

L04 网页执行方案还要求填写已接受的 `WB-L04-BOOTSTRAP` 任务编号，并展示独立复验人与接受人。必须先由学生直接监督 Codex 完成 V0，再由非构建者独立复验、签收；不能让库存导出的一次绿灯替代工作台验收。操作步骤见 [L04 工作台独立验收衔接](../courses/L04/实践操作手册.md)。这项检查验证职责记录，不提供身份认证或真实学习证据认证。

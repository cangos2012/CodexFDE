# 在工作台运行 Eval Harness

从工作台首页进入原事项，在“结果与证据”查看“Eval Harness · 候选质量检查”。这里展示逐项通过、阻断失败、观察告警、耗时、证据与错误，以及命令、候选指纹和报告路径。旧项目未提供耗时时显示“未记录耗时”，不补造数据。

项目交付仍自动运行原有检查。需要再次检查时，点击“重新运行候选检查”：工作台使用本轮方案保存的项目 Eval 命令，在原隔离候选中运行，不调用 Codex 修改代码。需要开启工作台代码执行能力、有已确认项目检查命令，并处于待验收或返工阶段；课程 V0 的既有入口保持原流程。

每次复验使用新报告目录，旧失败不覆盖。检查期间禁止重复提交与人工接受，可以停止本轮。有效阻断失败进入返工；执行异常、空结果、错误汇总、退出码矛盾或检查期间候选源码变化，都不能形成通过结论。复验本身不会将返工任务提升为已接受状态；代码修订仍通过原事项交付流程完成。

来源状态区分“当前一致”“已变化”“无法读取”和“未绑定”。已绑定报告按候选源文件清单和报告文件哈希复核，发现变化会阻止接受。历史未绑定记录按旧流程保留，不伪称已做来源复核。源文件清单沿用项目快照边界，排除运行目录等；这不是安全沙箱或防篡改签名。

项目命令需输出完整 JSON 到 `{report_path}`，或将完整 JSON 输出到 stdout。必须包含非空 `results`：每项提供唯一 `name`、`level`（`blocking` 或 `observing`）、布尔 `passed`。建议提供 `duration_ms`、`evidence`、`error`。`summary` 必须与分项一致，包含 `total`、`passed`、`blocking_failed`、`observing_failed`、`decision`；兼容旧项目省略零值 `observing_failed`。阻断失败退出 1，否则退出 0。统一入口汇总已登记项目命令返回的检查，不替代对业务检查覆盖范围的审核，也不支持页面临时输入任意命令。

检查通过只表示本次检查覆盖的条件满足；独立具名复验与业务接受仍需实际完成。本功能不自动导入 L06 本地练习会话，也不将练习结果写成客户项目验收。

后端代码更新后需以原运行目录和原参数重启工作台，再刷新首页；仅刷新浏览器不会更新已运行的 Python 服务。

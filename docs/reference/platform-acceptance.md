## 2. 卡 A：交付一个真实来源，再提炼

## 5. 隔离失败治理卡

**目标**：验证失败能阻断接受并触发流程版本治理，保留失败前后因果关系。构造故障仅使用独立验收运行目录及其隔离候选；不修改客户源码或客户数据来制造红灯。

| 故障操作与位置 | 应观察的真实结果 | 必留证据 |
|---|---|---|
| 在隔离事项/候选准备错误的本类型表头回归，或在隔离试用流程 v2 中指定一个实际不存在的必需文件；先在方案中说明故障范围并获得真实授权 | 阻断 Eval 或阶段检查失败；任务保留失败/返工状态，不能接受或集成 | 隔离项目基线、绑定版本、故障 Diff、失败报告及停止原因 |
| 使用已采用流程的隔离失败任务核对治理 | 记录 `outcome.passed=false` 与 `reuse_failed`；对应工作流版本被停用，旧绑定和历史快照仍可查看 | 失败任务编号、流程资产状态/历史、停用原因 |
| 重新调研另一隔离事项，默认召回同一主题 | 被停用版本不进入有效匹配；排除原因可追溯 | 新召回编号、排除状态与原因 |
| 以被停用版本为依据修订候选 | 新版本保存 `supersedes` 关系；重新独立审核、试用和发布，旧版本不被覆盖 | 新旧版本、修订 Diff、审核与再试用证据 |
| 候选 Eval 通过后，在授权的隔离故障实验中修改候选或替换报告，再尝试接受 | 报告/候选漂移被拒绝，不能凭旧绿灯接受；实际进程回执缺失也应阻断 | 漂移前后哈希、拒绝结果、重新复验记录 |
| 预览计划准备后改变预览配置；或原预览仍在运行时准备不同候选/配置的新计划 | 旧计划失效；旧进程不能冒充新的候选/配置。必须重新核对正确计划 | 新旧 plan/config/candidate 身份、返回结果或拒绝记录 |
| 在隔离运行中暂停、取消或重启 | 当前本地进程终止且证据保留；旧一次授权失效；不会重放旧任务。恢复核对候选 SHA 并生成新 attempt | 控制事件、新旧 run/attempt/候选身份、授权记录 |
| 切换事项或模拟读取失败 | 旧绿色证据不出现在新事项；写操作冻结，未提交文本保留。恢复草稿不填署名、授权或验收决定 | 失败界面/响应与恢复前后的字段状态 |
| 页面保持打开时重启隔离工作台服务，或将同地址切换到另一个运行数据库 | 服务/数据库实例头变化后，全局决定、运行、配置、预览和发布操作冻结并保留草稿；旧实例请求被后端拒绝，不自动采用新身份，须重新载入核对 | 新旧实例编号、409 `instance_changed` 响应、实际副作用数量、冻结界面与草稿 |
| 同一新写请求重复提交，或响应不确定后使用同键核对 | 不重复启动/生成/部署；pending 明确要求读状态，不能显示可授权的新成功计划 | submission_key、原请求状态、实际副作用数量 |

# 生成发布证据索引

证据索引回答“要求、修改、检查和人的决定在哪里”。它帮助复验者找到原始材料，不替代材料内容的审查。

任务建立后即可生成草稿，尚未取得的证据会列为缺项。把下列任务编号替换为实际编号，在项目根目录运行：

**Windows（PowerShell）：**

```powershell
.\.venv\Scripts\python.exe -X utf8 -m workbench.cli course-release-index TASK-实际编号 --runtime-dir .runtime
```

**macOS（zsh）：**

```zsh
./.venv/bin/python -X utf8 -m workbench.cli course-release-index TASK-实际编号 --runtime-dir .runtime
```

取得实际冷启动记录、产品对账和剩余风险说明后，把这些文件保存在本次运行目录中，再重新生成索引：

**Windows（PowerShell）：**

```powershell
.\.venv\Scripts\python.exe -X utf8 -m workbench.cli course-release-index TASK-实际编号 --runtime-dir .runtime --cold-start-evidence .runtime/cold-start.json --product-evidence .runtime/product-check.json --risks-file .runtime/remaining-risks.md
```

**macOS（zsh）：**

```zsh
./.venv/bin/python -X utf8 -m workbench.cli course-release-index TASK-实际编号 --runtime-dir .runtime --cold-start-evidence .runtime/cold-start.json --product-evidence .runtime/product-check.json --risks-file .runtime/remaining-risks.md
```

这些路径指向你实际采集的文件，命令不会替你创建证明材料。输出的 `path` 是索引位置；每次生成一个新目录，旧索引保留。

## 怎样阅读结果

- `references`：Spec、前后检查报告、进程收据、改动摘要及补充材料的相对路径与 SHA-256。移动文件后须重新核对路径。
- `evidence_gaps`：缺失、空白或发现不一致的证据。冻结后的 Spec 被改变、报告汇总与任务记录不一致也会列入。
- `task_status` 与 `human_review`：直接取自任务记录。待人审就显示待人审，不因报告通过而补上批准人。
- `diff_excerpt`：执行器保存的改动摘要，可能被截短，不能作为完整可应用 Patch。具名接受后的候选导出仍使用 `course-candidate-export`。
- `index_status`：始终要求人工审阅。退出码 0 表示成功生成索引，不代表可以发布或学生已经结业。

文件存在、指纹稳定和字段齐全都不证明内容足以验收。复验者仍要判断需求是否此前未实现、失败是否来自产品缺口、产品结果是否一致，以及剩余风险是否如实说明。

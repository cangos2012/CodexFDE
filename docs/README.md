# Codex AI 工程交付行动营｜学生学习入口

> **用 Codex，搭建个人 AI 研发工作台；通过工作台组织人与 AI 协同，持续开发 FlowERP。**

这页统一课程主线、逐讲阅读与行动入口、课件获取和排错说明。第一次学习从这里进入，再按当前讲次行动，不需要先遍历课表、大纲和蓝图。

最终交付两项相互配合的成果：能组织受控开发并保存证据的个人工作台，以及通过它持续开发的 FlowERP 客户产品。学生负责范围、授权、复验和接受决定；Codex 协助调查、实现与修复，工作台负责把这些过程组织起来。

## 先从这里开始

1. **第一次进入仓库**：按 [L00 课前准备](./courses/L00/README.md)安装工具、准备虚拟环境并完成环境自检，用 [L00 提交模板](./courses/labs/L00/SUBMISSION.md)记录实际结果。环境未通过时，先按手册排错，不进入正式开发。
2. **环境已准备好**：用 VS Code 打开 [课程工作区](./courses/FlowERP-AI研发工作台.code-workspace)，进入 [L01 本讲入口](./courses/L01/README.md)，按阅读顺序形成自己的首份需求、失败测试和工作台候选。
3. **已经在跟课或复习**：在下方 [16 讲学习路线](#16-讲学习路线)找到当前讲次。新学一讲先打开主题链接；需要回查原理、继续操作或核对提交时，直接使用同一行的资料链接。

不熟悉软件开发流程时，按需读 [从业务需求到上线：理解 Spec 与个人研发工作台](./reference/从业务需求到上线：理解Spec与个人研发工作台.md)，用库存导出看清需求、方案、测试与工作台的关系。

## 跟着一条故事理解课程

林舟为一个小型电商团队开发 FlowERP。运营周宁说明库存、订单与采购的困难，同伴陈珂独立复验，Codex 协助调查和实现。林舟起初没有个人工作台，先从自己的痛点出发，确认需求、形成测试并建设工作台；到 L04，才用独立验收的工作台 V0 交付第一份库存 CSV。

随后，重复收货、订单取消和采购审批暴露新的工程问题：检查可能漏错，报告可能不是当前版本，修复需要停止，协作需要固定输入，批准需要等待具体的人。每解决一次产品问题，工作台就补上一项可在下一次交付中复用的能力。后四讲把任务查询、页面、反馈与经验复用接起来，最后由另一位同学在新环境接手，现场提出一个此前未实现的小需求。

三位人物及其对话属于虚构教学设计。署明来源的真实运行、维护记录和参考实验按各自的证据边界阅读；人物故事与教学示意都不能替代你的实践记录。

![Codex、个人研发工作台与 FlowERP 的关系](./courses/assets/course-three-layer.svg)

读图时抓住两条关系：Codex 提供开发协助，工作台组织受控交付；FlowERP 的实际结果与失败再反过来检验工作台。人始终负责取舍、授权与签收。[可编辑源图](./courses/assets/course-three-layer.drawio)

## 四阶段怎样接起来

| 阶段 | 要解决的问题 | 你建设的工作台能力 | FlowERP 怎样验真 |
|---|---|---|---|
| L01～L04：工作台 V0 | 怎么把模糊诉求变成可验收的交付？ | 任务与证据记录、规则、Spec、受控执行 | L01～L03 不接入、不开发 ERP；L04 首次交付库存导出 |
| L05～L08：可信检查 | 能运行，为什么仍可能交付错误？ | Eval、Harness、Hook、同入口 CI | 幂等入库、统一可用库存、订单创建、原子预占 |
| L09～L12：受控协作 | 失败后改哪里、改几轮、交给谁、谁批准？ | 修复任务、有界 Loop、独立分工、Graph 与人审 | 取消释放、合法状态迁移、采购申请、审批后入库 |
| L13～L16：使用、反馈与接手 | 离开原会话和电脑，能否继续交付？ | 任务 API、Web、反馈与经验复用、冷启动 | 补货交付、客户操作页、真实反馈改进、现场新需求 |

**L04 是转折点。** 先接受工作台 V0，再由它组织 Codex 首次交付 ERP。此后沿同一条因果链继续：产品现场问题 → 工作台新增或验证能力 → 受控交付 → 结果与反馈回流。

同一个概念再次出现不代表重新开始：L01 手工形成首份 Spec，L03 把方法提炼成模板与解析器；L04 使用最小检查，L05 验证检查能抓错，L06 汇总多项检查，L07 与 L08 分别解决触发与远程复验。L04 已有人审，L12 再明确等待、打回和恢复规则。

产品能力持续积累，实验数据不持续累加。每讲示例数字属于独立测试条件；隔离候选不能覆盖已接受的产品。复用上一讲检查时，按手册核对真实加载的源码和用例名，同名入口不证明实现相同。

## 读懂理念，再判断怎样使用

各讲辅导资料把工程理念接到同一业务案例：L01～L04 解释证据优先、上下文工程、Spec 驱动与分层自主权；L05～L08 解释反例驱动、完整 Harness、最小权限与独立复验；L09～L12 解释内外循环、合同分工、持久化编排与人工介入；L13～L16 解释权威状态、经验与流程复用，以及可复现与可迁移的区别。

新增 ImageGen 配图已放在相应正文中。读图时指出一次正常流向、一个会被拦下的反例，以及谁依据什么作决定，再回到实践手册行动。图是教学机制示意；具体实现与个人完成情况要看源码和自己的执行证据。[配图总览与对应讲次](./courses/assets/advanced-concepts-20261003/README.md)用于复习，不增加必做任务。

## 每讲怎么学

1. **明确目标**：从本讲入口与案例写下要解决的问题、自己的首次判断和待确认条件。
2. **找到操作位置**：阅读辅导资料的相关机制图，再按实践手册确定仓库、隔离候选、允许范围和实际动作。
3. **比较预期与实际**：执行正常路径，按实验要求观察失败或反例，保存原始命令、退出码与失败后状态。规则前后都正确时如实记录，不伪造红灯。
4. **处理失败**：回到手册排错或恢复步骤；保留原失败证据，再在约定范围内修订，不覆盖已接受的产品。
5. **判断完成**：对同一候选复验，核对范围内 Diff、当前报告与业务状态，用行动卡整理个人记录，再由具名人员决定接受或退回。
6. **完成迁移**：换一个条件或小需求，独立说明方法怎样调整、什么证据支持结论，再进入下一讲。

参考实现已存在、Agent 自述“完成”或一张绿色截图，都不能替代你自己的判断、修订与复验。缺少运行或人审时保留待办，不因教材的叙述把个人状态填成已完成。

按手册启动当前已建成的工作台版本后，从 `http://127.0.0.1:8001/` 首页“事项与决策”继续组织需求与交付；自定义端口时仍使用根路径 `/`。首次建设和启动按 L00 操作。

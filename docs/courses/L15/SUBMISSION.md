# L15 提交模板

填写个人真实记录；无证据处标为未完成，不保留虚构示例。

## 1. 首次判断与修订

本讲 FDE 问题：原反馈者想完成什么工作，为什么采纳这个小改进而暂缓其他方案，何时需要重新判断？

- 问题来源及影响对象（实际观察／同伴试用／教学设置）：
- 本人的范围选择、暂缓项和理由；业务口径由谁确认：

后文已有的失败、修订、复验和迁移记录承接此判断，不重复填写。

空白导出说明什么：

检查全绿是否可以写已发布：

接受反馈能否直接改变阻断规则：

复验后如何修订、依据是什么：

## 2. 摘要与周报

源事项 / Task / 候选 / 需求版本：

摘要与引用文件：

周报窗口、统计单位、待审与返工处理：

## 3. 反馈三层记录

来源角色、日期、场景、版本、记录许可：

## 4. 个人建设与失败

具体 Spec、允许写集、新增用例与起始版本：

既有 / 新增检查的真实逐项结果与退出码：

后续 Task、实际 Diff、独立 Eval、业务对账：

非法反馈 / 违规晋级失败后，原记录和规则是否保持：

## 5. Memory 记录

Memory ID、项目、业务对象与版本：

结论、适用条件与不适用条件：

状态、实际审核者与时间、替代或撤回关系：

个人记忆集绝对路径、实际文件版本与来源修复 Task：

高相似撤回条目的失败实验与过滤结果：

## 6. RAG 检索、引用与评测

新事项、原始查询、查询改写与项目过滤：

显式传入 --fixture 的个人文件、实际命令与退出码：

人工确认的相关记忆集合与理由：

Top-k 结果、分数、Precision@k、Recall@k、空结果：

上下文快照、SHA-256 与 `memory_id@v版本` 引用；source.task_id 是否回到第 5 步的个人修复：

Codex 建议中的关键断言、引用是否支持及冲突：

采用／拒绝／补查决定、决定人和理由：

## 7. 人的复验与迁移

具名交付决定：

第二事项及不同于来源任务的后续 Task；采用的记忆来源、版本、快照、理由，实际 Diff、新 Eval、业务结果与具名审核：

复用失败属于检索、记忆、生成、执行还是业务判断，怎样修订或停用：

Skill 首次预测、真实输出、漏判与修订：

尚未完成的事项、责任人与下一步：

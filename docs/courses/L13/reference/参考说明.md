## 1. 受理、执行与完成的身份

HTTP 请求、Task 和采购单拥有不同身份。202 表示受理，review 表示候选待决定，completed 必须有对应接受依据；采购批准和收货是客户业务事实。

提交键还须有作用域、内容指纹与冲突语义，不能只按字符串去重。任务持久化、Spec 文件写入、执行副作用及事件记录是不同故障点，应分别定位最后可靠状态。

## 2. 重启证据怎样判断

重新打开数据库对象不是服务进程重启；保存两次实际进程、同一运行目录、原 Task ID 与完整 HTTP 查询。重启中的 running 任务和已完成任务需要分别观察，不能把后者的持久读取推成前者自动恢复编码。

接口路由按实际入口核对，同名 URL 不能跨服务借用。教学实验使用 verify 和教学审核字段，不证明 Codex 编码或真实人的接受。

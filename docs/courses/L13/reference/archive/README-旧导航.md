# L13｜把执行链路封装成任务 API

## 第一次打开，按这条路线走

本讲支持 Windows PowerShell 与 macOS zsh；[实践手册](../../实践操作手册.md)逐步给出各自解释器命令。新终端回到记录中的控制仓库，服务窗口和操作窗口分开保留；中断后续查原 Task 与原运行目录。

用任务 API 提交和查询同一任务，并在进程恢复后找回证据。

**开始前准备：** 可执行的交付链路与隔离运行目录。

| 顺序 | 打开什么 | 现在做什么，做到哪里再继续 |
|---|---|---|
| 1. 看懂本讲任务 | [辅导资料](../../辅导资料.md) | 先读开头的案例或总览，写下本讲要解决的问题；原理随实践回查 |
| 2. 开始操作 | [实践操作手册](../../实践操作手册.md) | 手册第 1～3 步：预测结果，观察 HTTP 与中断恢复；能区分提交成功、任务完成和采购入库 |
| 3. 完成本人实现 | [实践操作手册](../../实践操作手册.md) | 第 4～5 步：实现两个接口并接回 FlowERP |
| 4. 复验与交接 | [行动卡](行动卡.md)及手册末尾 | 第 6 步：失败、重启恢复、业务结果与同伴复验 |

**个人记录放哪里：** SUBMISSION.md；记录任务 ID、接口结果和恢复前后状态。报告、截图和教师示例用于对照；个人结论填写实际观察，尚未复验就注明待复验。

## 遇到问题，回到哪个入口

- 看不懂业务规则或判断理由：回到辅导资料的对应案例。
- 不知道在哪输入、缺少文件、命令报错或中途重开窗口：回到实践手册的准备、排错或恢复步骤，先确认原会话与候选。
- 不知道某个脚本能否直接运行：先查手册是否调用它；参考实验与个人交付按手册区分。
- 同一主题有多份 PPT、图或历史记录：按课堂指定版本使用；首次自学以当前辅导资料和实践手册为主。

下载或移动附件时保留本讲目录结构；只拷贝一个 Markdown 文件可能导致配图、Prompt 或脚本路径失效。

## 按需参考：已有实验说明与资料记录

提交成功、研发交付完成、采购入库是三个不同的事实。本讲以补货需求串起任务身份、异步执行、幂等提交、持久状态和恢复，让离开页面后仍能找回同一任务及其证据。

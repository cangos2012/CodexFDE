## 第八步：检查 B 的导出结果

在控制项目根目录运行以下整段命令，提示时填 B 编号。脚本自动准备练习数据，在 B 的候选上检查五组情境，不修改日常数据库。

```powershell
$L04Python = (Resolve-Path .\.venv\Scripts\python.exe).Path
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
$OutputEncoding = [Console]::OutputEncoding
$L04Probe = (Resolve-Path docs/courses/L04/scripts/check_inventory_delivery.py).Path
$L04B = Read-Host '填写实际 B 任务编号'
$L04TaskText = & $L04Python -X utf8 -m workbench.cli task-show $L04B --runtime-dir .runtime/l04-learning
if ($LASTEXITCODE -ne 0) { throw '无法读取 B，请检查编号与运行目录' }
$L04Task = $L04TaskText | ConvertFrom-Json
$L04Isolation = $L04Task.events | Where-Object { $_.detail -eq '已创建课程隔离 Worktree' } | Select-Object -Last 1
if (-not $L04Isolation.evidence.path) { throw 'B 尚无隔离候选，请回查执行记录' }
$L04Candidate = (Resolve-Path -LiteralPath $L04Isolation.evidence.path).Path
$L04Evidence = Join-Path (Get-Location).Path ('.runtime/l04-check-' + [guid]::NewGuid().ToString('N'))
& $L04Python -X utf8 $L04Probe --workspace $L04Candidate --output $L04Evidence --case all --file-entry flowerp.inventory_export:export_inventory_file
$L04CheckExit = $LASTEXITCODE
if (Test-Path -LiteralPath (Join-Path $L04Evidence 'report.json')) {
    Get-Content -LiteralPath (Join-Path $L04Evidence 'report.json') -Encoding UTF8
} else {
    throw '未生成 report.json，请保留本次终端错误与证据目录，先排查检查程序'
}
if ($L04CheckExit -ne 0) { throw '检查失败或缺项，保留报告并按第十步返工' }
```

打开输出目录的 `report.json`，应有五组 `pass`：

| 检查项 | 要核对的结果 |
|---|---|
| `normal` | 东仓 8−3=5，西仓 12−4=8；两条明细、八列，东仓在前 |
| `empty` | 只有表头，0 条数据 |
| `special` | 名称中的逗号、引号、换行读回后不变 |
| `ordering` | 商品、仓库、仓位、批次逐级排序 |
| `file-failure` | 正常写出成功；中途失败保留旧文件，无旧文件时不留目标半成品 |

各情境还须核对库存与流水前后不变。入口缺失返回 2，检查失败返回 1，全部通过返回 0；未触发预定写入异常也算失败。

继续在同一终端运行，亲自导出文件：

```powershell
$L04Database = Join-Path $L04Evidence 'normal/practice.db'
$L04CSV = Join-Path $L04Evidence 'inventory.csv'
Push-Location -LiteralPath $L04Candidate
try {
    & $L04Python -X utf8 -m flowerp.inventory_export --database $L04Database --output $L04CSV
    $L04ExportExit = $LASTEXITCODE
} finally { Pop-Location }
if ($L04ExportExit -ne 0) { throw '文件导出失败，保留错误并返工' }
Import-Csv -LiteralPath $L04CSV -Encoding utf8 | Format-Table
```

将两条记录与 `normal/expected.json` 比较，批次以本次实际生成值为准。`inventory.csv` 是产品入口写出的文件，交给需求确认者核对用途。

## 第十步：有失败时，按问题返工

| 遇到什么 | 做什么 |
|---|---|
| 页面没有任务 | 核对网页和命令均使用 `.runtime/l04-learning`，刷新“交付记录” |
| A 在 `review`，需要修改 | 审核者先打回返工；建设者修复后，同伴重跑第五步的 `task-run` |
| A 已由建设者运行，缺独立复验 | 保留旧 A；建设者另建 A，引用旧编号，交同伴运行和审核 |
| A 已完成但控制源码变化，或 A 为 `failed` / `dead_letter` | 保留旧记录，修复后新建 A，重新独立复验并接受 |
| B 的 CSV 或文件保护失败，工作台如实留证 | 审核者打回 B；将原 B 编号、报告和修订要求交给执行提示词，重新执行第七步，再检查新 B 候选 |
| 工作台漏报越界、吞掉失败，或状态与真实结果矛盾 | 暂停 B，先修复并重新接受 A，再提交 B |

`review`、`completed` 状态不能直接重复 `task-run`。每轮保留原失败记录；新 B 使用新候选和新检查目录。仍未完成时，在第九步如实填写待处理项。

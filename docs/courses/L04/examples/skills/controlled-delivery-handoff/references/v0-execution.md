# V0 建设与首次执行指南

在 A 建设时读取建设表，在实际执行或需要过程截图时读取后两节。路径是当前课程参考实现的定位线索，执行前核对实际源码与命令帮助，不要求学生另建同名重复模块。

## 把前序成果接起来

| 本轮连接 | 调查落点 | 实施与检查 |
|---|---|---|
| Spec → 任务 | workbench/spec.py、任务账和合同绑定入口 | 复用六段解析；任务能回查所用内容。有效输入可记录，缺字段明确拒绝，不启动编码 |
| 任务 → 执行 | workbench/workflow.py、实际执行器 | 明确模式、目录、写集和超时。仅复验不编码；真实执行缺少必要写集时拒绝；失败输出可追溯 |
| 执行 → 范围与 Eval | 执行器的变化采集、eval/ | 检查完整实际变化和命令退出码。范围内正常请求能继续；退出 0 但越界仍失败；超时不转成功 |
| 结果 → 摘要与人审 | 任务持久化、报告与审核入口、workbench/bootstrap_handoff.py | 摘要回指原始记录，程序通过保持待审核。A 接受与源码绑定，变化后不能借旧接受启动 B |

每个连接先指出“原有代码负责什么、缺什么、准备改哪里”，按用户已批准的范围实施。把本人对规则和验收的取舍写入现有记录即可，不另建繁琐填表流程。

可参考的针对性检查包括 tests.test_workbench、tests.test_execution_streams 和 tests.test_bootstrap_handoff。先查看用例是否触及本轮缺口，再选择运行范围；测试文件不存在属于起点差异，不能作为目标行为红灯。测试替身可验证控制分支，真实 Codex 调用需单独证据。

## 实际执行时观察什么

使用项目 .venv。先识别控制目录、候选目录和各自的解释器，避免在原仓库验证另一个候选。运行记录保存在独立目录，课程运行数据不进入业务 Diff。

| 阶段 | 操作 | 必须观察的结果 |
|---|---|---|
| A 建设 | 调查前序成果，实现批准的缺口，检查实际 Diff 并重跑同案检查 | 实际实现文件与来源要求对应；正常和失败分支均有结果 |
| A 复验 | 用能力合同创建任务，运行针对性检查及任务复验，交给实际同伴 | 被测版本、真实结果与具名决定能够对应；仅自动复验不算独立接受 |
| B 启动 | 按实践手册调用 course-submit --lesson 4 --execute-code，传真实 A、Spec、actor、运行目录及超时 | 返回真实任务与候选；未满足前提时明确拒绝 |
| B 执行 | 观察工作台调用 Codex 的事件，查看实际变化及检查 | 区分事件记录、实际文件和模型自述；失败留下原因与候选 |
| B 复验 | 在同一候选读取 CSV、比对业务状态与写集 | 结果满足确认版 Spec；未覆盖项如实标记 |
| 人工决定 | 实际复验者检查同一版本并作决定 | 接受或打回有来源，不自动等同合并发布 |

用户通过 Web 操作时使用工作台首页“事项与决策”。后端命令用于建设或复验，不另造日常研发入口；首页未贯通部分如实标记。不要因为需要截图就启动未被当前任务要求的服务。

## 过程截图与交付说明

截图要回答一个具体问题，并指向同一步的原始材料：

- 前序输入：AGENTS、两类 Spec 的路径与内容，说明采用哪版规则和要求。
- 建设范围：真实调查或 Codex 交互，说明本人确认了哪些缺口与文件。
- 建设变化：实际 Diff 和新增文件内容，说明哪条连接已经实现。
- 同案检查：命令、输入、退出码与结果，说明失败是否按预期处理。
- 执行交接：真实 A/B 编号、候选与 Spec，说明本次采用关系。
- 待审核或返工：当前状态与原始检查，说明下一步需谁判断什么。

按实际发生的步骤选择截图，不追求固定张数。原生界面截图、命令输出排版图、示意图分别标注；不得为截图补造执行、前红后绿或签名。截图不可用时保留文本并说明限制。截图只是阅读入口，不能取代完整命令、Diff、CSV 和状态记录。

最终交付说明应让用户直接回答：我的 V0 本轮建成了什么，如何用它完成这次客户变更，失败怎样处理，现在还差哪个具体决定。直接使用已有记录，不要求额外提交模板。

# 建成工作台 V0，再通过它组织交付

L04 的首要成果是可用的个人研发工作台 V0。承接 L01 的工作台 Spec、任务与命令证据账，L02 的 AGENTS 规则，L03 的 Spec 模板与解析器，补齐执行、范围检查、最小 Eval、摘要与人工确认。库存导出是 V0 的首次客户交付与验证场。

保留两个任务边界：Ticket A 由学生直接监督 Codex 建设工作台并交给实际独立复验者接受；Ticket B 由已接受的 V0 组织 Codex 修改 FlowERP。工作台能力合同和库存导出业务 Spec 分别引用。

## 先判断现在该做什么

从用户请求和实际文件判断阶段，不要求一开始就提供尚未产生的 B 编号或验收记录。

| 当前情况 | 开始位置 |
|---|---|
| 要完成 V0，或已有 AGENTS、Spec 但执行链未接通 | A 的调查与建设 |
| V0 已实现，需要复验或准备同伴审核 | A 的复验与版本交接 |
| A 已独立接受，要实际交付库存导出 | B 的受控执行 |
| 只要求检查、解释或编辑材料 | 在指定范围处理，不启动编码、任务或服务 |

核对实际仓库的 AGENTS、L04 合同、相关源码和用户前序成果。课程文件默认位于 `docs/courses/L04/`，不要依赖固定盘符；skill 被复制到其他位置时从项目查找。缺失输入先定位，只有影响下一步的必要决定无法确定时才询问。沿用会话已有授权，不重复确认已批准的范围。

## A：依据规则与规格把 V0 建出来

1. **盘点起点。** 找出前序工作台 Spec、AGENTS、Spec 解析器、任务／证据账和当前执行入口。形成简短对应表：来源要求、已有入口、真实缺口、本轮改动、可观察验收。缺少前序能力时明确补齐范围；参考终态已经实现的部分如实列为已有。
2. **确定增量合同。** 沿用工作台原有目的，写明本轮 V0 目标、非目标、约束、正常与失败验收及完成条件，并回指前序版本。使用项目的六段 Spec 结构。由学生作出的范围与验收取舍要可见，不用库存字段要求代替工作台能力要求。
3. **分段实现。** 按“Spec 接入任务 → 任务接入受控执行 → 实际差异接入范围检查与最小 Eval → 结果接入摘要与人工确认”补齐连接，复用现有模块。进入 A 建设时读取[建设与执行指南](references/v0-execution.md)。
4. **同案复验。** 在批准范围实施缺口，保留实现前真实结果、建设 Diff 和同案复验。检查正常请求能继续、无效输入／越界／超时会按要求停止。已有检查为绿时不删除功能造红；环境失败与目标能力失败分开记录。
5. **独立接受。** 交出能力合同、具体源码版本、建设变化、针对性检查及剩余缺口，供实际同伴亲自复验。自动测试通过和姓名字段不能替代独立接受；不得用第二个 Agent 或虚构身份扮演同伴。缺少人审时完成仍可独立处理的 A 工作，状态保留待独立接受。

A 的接受必须对应当前控制源码与实际运行版本。源码发生变化后按现有机制重新复验并接受，必要时更新运行进程。指纹覆盖范围由实际实现决定，不宣称它锁定整个环境，不手改数据库来续用旧接受。

## B：用 V0 验证首次真实交付

A 有效后核对 L03 确认版业务 Spec 的实际内容、控制运行目录、独立候选、源码起点、解释器和最小写集。课程目录上限不是本次全部授权。输入无效时先修正输入；不得绕过工作台直接完成业务代码来冒充 V0 交付。

用户已授权执行时，通过当前工作台支持的入口实际运行，核对 `course-submit` 的参数，将 `--bootstrap-task-id` 与 `--requirement-spec` 绑定到真实材料。只读请求停留在核对阶段。执行细节与截图要求按需读取[建设与执行指南](references/v0-execution.md)。

依次展示任务绑定、候选起点、执行事件、实际 Diff、检查结果与待审核状态。所有新增、修改、删除和重命名均需核对，未跟踪文件须单独查看；审核者的检查必须运行在 B 的同一候选。执行中暴露 V0 缺口时保留现场，返回 A 修复及重新接受，再判断 B 的恢复点。

库存导出按确认 Spec 检查字段、数量、行粒度、排序、空集、特殊字符、写失败及库存／流水前后不变。默认 Eval 未覆盖的要求单独补验或标记未验证，不把进程退出 0 当业务通过。

## 给用户看到过程与结果

在关键状态变化时说明“刚执行什么、实际看到什么、接下来检查什么”。代码建设展示实际改动与同案复验；截图附命令或操作、对象路径／任务编号与观察点。保留原始输出，标注原生界面、真实输出排版、示意或测试替身；不把参考截图、测试夹具或模型报告写成学生建设与人工接受。

按当前阶段给出简短结果：

- A：本轮接通了哪些 V0 能力，依据哪条规则或 Spec，修改在哪里，怎样验证，独立接受是否完成。
- B：采用哪版 A 和业务 Spec，实际交付了什么，候选与 Diff 在哪里，哪些检查通过或失败，谁还需作决定。

直接沿用用户已有任务记录和交付说明，不要求另填固定作业模板。分别报告执行结束、检查结果、人工接受；未经事实支持不延伸为合并、发布或线上效果。一次成功也不表示记忆系统与工作流蒸馏已完成跨事项复用。

修改本 skill 或排查阶段误判时，读取[情境检验](references/handoff-cases.md)。它用于只读推演；实际行为验证应另行记录真实输入、响应和遗漏，不把表中的预期结论当测试已通过。

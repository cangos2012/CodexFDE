# L04｜委托 Codex 执行一次最小变更

**FDE 衔接**：先读[讲义中的 FDE 安排](辅导资料.md)，确认库存导出的使用者、用途和范围；先验收 V0，再由 V0 组织客户交付。展示时关联现场判断、真实结果与可复用方法，并解释 L05～L16 将如何继续验证。

目标：依据 L01 工作台 Spec、L02 AGENTS 与 L03 解析能力，亲手补齐并独立验收个人工作台 V0，再由它组织 Codex 交付 FlowERP 库存导出。

## Ticket A：工作台 V0

- [ ] 记录实际仓库、解释器、Codex 版本和控制运行目录。
- [ ] 盘点 L01 工作台 Spec 与任务／证据账、L02 AGENTS、L03 模板与解析器，区分已有支架和本讲缺口。
- [ ] 依据已有规则和工作台 Spec 写 V0 增量合同；与留给 Ticket B 的库存导出 Spec 分开保存。
- [ ] 为每项增量写出“来源要求 → 程序责任 → 正反检查”，核对实际入口和最小写集。
- [ ] 依次接通 Spec 与任务、受控执行、范围检查与最小 Eval、摘要与人工确认，复用已有能力。
- [ ] 锁定 L03 确认版业务 Spec；结构或确认状态无效时停止 Ticket B。
- [ ] 写明 V0 的五类情境：仅复验、缺写集、失败／超时、越界、待人审。
- [ ] 先检查当前实现，确认真实缺口，不制造假红灯。
- [ ] 监督 Codex 做最小变更，保留首次输出、退出码和完整 Diff。
- [ ] 建设后重跑同一要求，说明测试替身能证明什么、不能证明什么。
- [ ] 由另一位复验者亲自检查并接受具体源码版本。
- [ ] 建设者用针对性测试自查，新建 A 由同伴运行；已在 `review` 的 A 不直接再次 `task-run`，按实践手册的状态表处理。
- [ ] 改变控制源码后，确认旧接受失效；恢复后重新复验。

## Ticket B：库存导出

- [ ] 同时提供实际 Ticket A 编号和 L03 确认版 Spec。
- [ ] 核对 `lesson-03-submission/FDE_SPEC.md` 的实际路径、确认记录与文件摘要，不能以初稿解析通过代替业务确认。
- [ ] 保存 Ticket B 编号、独立候选目录、源码起点和实际执行状态。
- [ ] 检查新增、修改、删除和重命名；每项变化都能回指需求或必要依赖。
- [ ] 确认没有密钥、`.env`、运行数据库、报告产物和无关业务改动进入 Diff。
- [ ] 在同一候选运行阻断检查，不到原仓库验证另一份代码。
- [ ] 按列读取真实 CSV：8、3 得 5；12、4 得 8。
- [ ] 检查八列、多仓位／批次、排序、空集、特殊字符和写失败。
- [ ] 按实践手册运行[库存交付检查脚本](scripts/check_inventory_delivery.py)，保留真实 CSV、前后数据库内容和退出码；检查报告只对应实际覆盖的入口。
- [ ] 文件失败实验调用候选的真实写入入口；缺少入口或故障未触发时保留缺口，不用教学留证写入代替产品文件保护。
- [ ] 比较导出前后库存与流水，确认成功和失败都保持只读。
- [ ] 将摘要回查到原始 Diff、命令、退出码和文件；未运行项写“未验证”。
- [ ] 由实际复验者接受或打回，并写明剩余风险。

## 三个不能混淆的结论

- Codex 进程结束：只说明执行阶段结束。
- 独立检查通过：只说明被检查的行为符合预期。
- 人工接受：只表示具体候选可进入下一步，不表示已经合并、发布或上线。

## 附录：本讲课程合同

对应 CLO-2。以下四项沿用正式大纲；FDE 引导细化判断与学习证据，不增加机器通过门槛。

- **核心内容**：非交互执行、工作目录、权限边界、结果采集与人工确认点。
- **演示结果**：读取第 3 讲 Spec，委托 Codex 完成一个小型代码变更并运行测试。
- **课内增量**：先由学生直接监督 Codex 补齐并独立验收 Workbench V0 的执行入口、写集检查、最小 Eval 和结果摘要，再由 V0 在授权工作区调用 Codex 交付库存导出；不额外包装为文件读写 MCP。
- **通过标准**：变更能够运行；基础测试通过；摘要包含修改文件、验证命令和剩余风险；密钥和环境文件未提交。

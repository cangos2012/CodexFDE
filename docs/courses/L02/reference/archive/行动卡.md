# L02｜把仓库规则写进 `AGENTS.md`

本卡承接[辅导资料](../../辅导资料.md)与[实践操作手册](../../实践操作手册.md)。具体命令、文件名及提交内容以本讲手册为准。

1. 先记录现场问题和首次判断，说明本讲工作台能力与后续 FlowERP 交付的联系。
2. 由本人确定范围和授权，与 Codex 完成本讲实现；保留自己的改动和运行结果。
3. 按手册检查正常路径、失败路径和失败后状态，修订后用同一条件复验。
4. 按手册提交原始证据、同伴反馈和迁移判断。参考仓库通过不代表本人完成。

本讲由你直接监督 Codex 查明事实、起草规则，由你决定取舍，同伴复核一项判断。FlowERP 业务账不变；工作台新增跨会话协作约定，为后续 ERP 交付保留业务与验收边界。对应 CLO-1 的个人证据是：能解释一条规则的来源，用越界与合法请求检验它，并根据反馈修订。

先以“记录完整仍待审核”解释规则为何成立，再迁移到采购审批情境。N0/N1 的请求差别要如实记录；规则修订后同时复测相关越界与合法请求。引用正确、载入已验证、程序检查通过应分别给出结论。


## 结构判断衔接

将已确认的结构、调用限制和具体代码示例写入规则，区分当前事实与待调整项。

本人记录应保留采用理由及实际依据，不能以 Codex 自述替代核对。

## 大纲四项合同

以下逐项引用现行课程大纲，正文示例不替代当讲通过标准。

- **核心内容**：Prompt、`AGENTS.md`、Skill、Hook、MCP 的职责边界；最小而有效的项目约束。

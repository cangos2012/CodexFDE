# 委托一：确认事件与来源

请阅读我指定候选中的项目 Hook 配置、处理器和统一 Harness。当前候选路径：____；任务范围：____。这一步只调查，不启用 Hook。

从“最后一次订单修改可能漏跑检查”推导适合的事件。列明调用链、解释器、实际 cwd、配置来源、重入分支和两层超时。区分 Stop 与 Git Hook，说明副作用已经发生后还能处理什么。

对草稿订单核查两行金额、非法数量、第二行商品不存在和库存不变。指出默认用例覆盖与本次要求的差距。输出有文件依据的事实、待确认项和建议范围；不要将未运行的事件写成已验证。

先用销售登记两行草稿订单的具体操作说明现场困难。金额、非法输入后的三表状态与创建不预占分别由什么检查负责？最后一次检查与最后一次修改的顺序怎样证明？不要仅确认配置文件存在。

先不要预设需要 Stop Hook。比较最后一次修改与最后一份报告，检查覆盖、候选来源和执行是否完成。分别列出缺少断言、测错候选、环境故障与触发遗漏的依据；证据不足时保持待确认。给出改 Eval、运行环境或事件连接的顺序，由我确认诊断。

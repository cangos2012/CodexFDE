## 1. 协议字段与两层退出码

查看完整输入和输出，再读退出码。以下对应课程参考处理器与工作台绑定处理器，不推广为全部 Hook 的通用格式。

| 字段或通道 | 深入核对点 |
|---|---|
| `hook_event_name` | 两份当前处理器均要求 `Stop` 事件对象。 |
| `cwd` | 解析后的目录须是处理器所属或绑定候选，或其子目录；不能指向控制仓库来代替客户候选。 |
| `stop_hook_active` | 重入时跳过检查；工作台绑定处理器还要求它为布尔值。跳过没有新的质量结论。 |
| `decision: block`、`reason` | 表达续跑请求及原因；检查宿主实际响应，后续动作仍受原授权约束。 |
| `continue: true`、`systemMessage` | 允许继续结束流程；须读消息区分“检查通过”与“重入跳过”。 |
| `stdout`、`stderr` | stdout 是完整 JSON 响应；诊断进入 stderr。不要从混杂输出中截取一段 JSON 冒充协议成功。 |

内部检查非零，处理器仍可退出 0：前者表示检查失败，后者表示成功返回协议。若处理器异常退出且没有完整响应，只能记录反馈未完成，不能推断宿主已收到 block。工作台绑定路径还验证报告结构、用例与退出码的一致性；仅出现“pass”文字不足以放行。

源码：[课程参考处理器](../../../../.codex/hooks/quality_gate.py)、[绑定处理器](../../../../workbench/quality_hook.py)、[项目报告校验](../../../../workbench/eval_harness.py)。

## 2. 课程组合候选与日常独立项目绑定

先识别正在用哪种接入，不能把待审文件和命令混装。

| 核对项 | L07 课程组合教学候选 | 工作台日常独立项目 |
|---|---|---|
| 如何确定候选 | 以本讲 `course-prepare` 返回的 `path` 为准，再在 `task-create` 中绑定此候选，核对实际起点与客户源码来源。 | 首页“事项与决策”的实际事项、任务和隔离候选；正式项目目录不能作为准备目标。 |
| 待审产物 | 候选中的 `hook_staging/hooks.json`、`quality_gate.py`，由本次课程任务交付。 | 运行目录 `hook-packages/` 中的 `binding.json`、`hooks.json`、`quality_gate.py`；每次准备保留新包。 |
| 内部检查 | 候选自己的统一 `eval.harness`，须确认本讲要求实际被选择。 | 绑定已确认的客户 `eval_command`，由 `CandidateProjectEval` 在客户隔离候选执行。 |
| 外层解释器与模块 | 个人实现须明确候选解释器、处理器所属目录及内部 cwd。 | 配置固定准备时的工作台解释器；处理器引用工作台模块绝对路径，客户无需安装工作台包。 |
| 可迁移边界 | 教学副本改动不自动写回独立 FlowERP。 | 依赖原工作台、运行目录与绑定包；移动目录后重新准备、安装并审查。 |

[当前源快照实现](../../../../workbench/course_snapshot.py)会为 L04+ 组合独立 FlowERP 源文件，写入 `.course/product-source.json` 的来源与哈希。`course-submit --execute-code` 则从本讲起始标签创建隔离 Worktree，不能仅凭命令名推断本次候选的来源；按实际起点和元数据核对。CodexFDE 日常目录仍不维护重复的 `flowerp/` 包。

首页准备绑定包要求事项处于待审核或返工、已有任务和候选，并确认质量命令。`binding.json` 固定事项、任务、候选、命令和指纹；安装时它保留在待审包中，活动配置与处理器安装到候选 `.codex`。绑定改变会返回未完成验证，不能手改旧绑定后沿用原审查结论。

网页的 `installed` 只表示安装文件匹配，`trust` 保持 `unknown`；它不读取 Codex 信任记录。调用记录默认 `evidence_kind=stop_input`、`host_event_verified=false`，即使保留 `session_id`，仍须与真实 Codex 会话对应。手工输入也能产生记录。

实现入口：[事项准备条件](../../../../workbench/initiative_workflow.py)、[绑定包与调用记录](../../../../workbench/quality_hook.py)、[独立候选检查](../../../../workbench/project_delivery.py)。日常接入操作查[工作台 Hook 使用说明](../../../reference/工作台-Hook-使用说明.md)。

## 3. 超时、异常与重入的完成边界

当前[参考配置](../../../../.codex/hooks.json)外层时限是 120 秒，[参考处理器](../../../../.codex/hooks/quality_gate.py)内部 `subprocess.run(timeout=100)`。工作台绑定包同样固定内层 100 秒、外层 120 秒，并复用受控执行器。内层更短是为了留出诊断、记录和协议返回时间；这些数字不是所有项目的固定标准。

绑定路径将超时、命令无法启动、取消、报告缺失或不合法记为未完成验证；保留 `project-reports/` 的进程输出，向宿主返回 block。普通业务失败与运行故障要分别定位。外层停止等待不能证明所有派生进程均已结束；实际进程生命周期仍要在本机验证。

重入分支不启动检查：课程参考处理器只返回跳过消息；绑定处理器另保留 `outcome=skipped`，不产生通过报告。续跑后修改了文件，应显式复验最终候选，再取得手册要求的新一轮正常 Stop 通过记录。旧报告、重入 continue 和界面结束都不能覆盖新版本。

[协议实验](../examples/hook_protocol_lab.py)通过替身抛出 `TimeoutExpired`，只能核对异常适配分支。[真实等待测试用例](../../../../tests/test_quality_hook.py)另安排实际等待程序检查超时；本次文档整理未运行该测试，不能据此报告本机已验证超时。

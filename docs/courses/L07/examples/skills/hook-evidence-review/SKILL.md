# Hook 证据复核

先确认用户本次要核对的是哪一阶段：业务规则、处理器协议、真实子进程、宿主事件或最终交接。按阶段给出结论，不因协议实验没有宿主事件而否定它的实验价值，也不把局部成功扩大为交付通过。

沿配置找到实际处理器、解释器、cwd 和被加载的业务模块。核对候选未提交修改、实际检查清单与本次报告；同一 SHA 或同名文件不证明工作树相同。来源不明确时指出缺口，授权范围内可执行只读核查与复验。

将三种结果分别写清：Harness 的分项及退出码；处理器完整 stdout 是否符合当前协议；宿主是否实际触发并消费响应。处理器退出 0 且返回 block 表示协议完成、内部失败待处理。人工输入、测试替身、真实子进程、真实宿主记录分别标识。

重入分支若没有调用检查，结论只能是跳过。比较报告指纹并检查最终候选有无新复验。异常、超时与缺报告记录未验证原因，不能用旧报告补位；模拟超时仅证明异常分支，实际终止需进程证据。

输出简短的“当前阶段结论、证据位置、矛盾或缺口、下一步”。Hook 安装、信任和审核应按用户实际授权处理；本复核不自动启用配置，也不生成他人接受记录。修订时保持失败证据及业务断言。

教学验证时读取 [反例与真实实验索引](references/review-cases.md)。先预测，再提供证据，保留实际响应与修订；下一个任务明确采用后才记录跨任务复用。

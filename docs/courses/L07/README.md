# L07｜用 Codex Hooks 建立本地护栏

订单改完后可能漏跑最后一次检查。本讲通过工作台交付草稿订单，把同一套质量检查接到 Codex Stop 事件，取得失败、修复和恢复证据。

第一次学习只沿着三份材料走：

| 顺序 | 打开什么 | 做到什么再继续 |
|---|---|---|
| 1. 理解问题 | [辅导资料](辅导资料.md) | 看懂订单漏检、Hook 与 Harness 的分工，先写自己的判断 |
| 2. 按步操作 | [实践操作手册](实践操作手册.md) | 第 1～4 节观察与设计；第 5 节取得候选、准备环境、接入检查；第 6 节安装、信任和真实触发；第 7 节复验与迁移 |
| 3. 留下证据 | [SUBMISSION.md](SUBMISSION.md) | 从开始就填写同一份个人副本，保留首次判断、失败、修订与实际审核 |

**开课前准备：**L04 已接受的控制工作台、独立 FlowERP 环境，以及自己的 L06 库存 session 和当前绿报告。尚无 L07 候选时按手册顺序做，不提前安装 Hook；已有原任务时沿用它。

“Hook 怎么加到 Codex”直接看[手册第 6 节完整链路](实践操作手册.md#6-把-hook-接入-codex取得真实失败与恢复证据)：同一候选 → 审查 → 安装 → 在 CLI 用 `/hooks` 信任 → 正常 Stop → 红灯 → 修复与新一轮通过。Windows 和 macOS 分别提供代码块。

课堂统一打开 [L07 当前课件（33 页）](L07-用CodexHooks建立本地护栏.pptx)。课件保留已有教学案例；处理器异常、内部超时与路径的旧描述尚待同步，实际操作以当前手册为准。

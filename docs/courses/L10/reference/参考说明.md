## 1. 决策轮与进展签名

当前 `agent.loop` 先检查再决定是否执行，修改后的代码在下一轮接受检查。因此最大轮数约束决策轮，不能直接当作执行次数。连续失败名称相同会停止；原因改善也可能被忽略，A/B/A 则不一定被此近似规则识别。

末轮执行后，最后报告可能仍对应修改前版本。循环外追加检查应独立保存，不能回填成旧 History 的内部收敛。

## 2. 用量、异常与写入范围

Token 在调用后累计，超额后停止下一轮，不是单次调用前的硬额度；缺少真实用量不能填零。默认入口不调用 Codex，实际执行分支也须检查调用对象和文件约束。`workspace-write` 和 case 列表不能充当逐文件授权。

外层 `runtime_dir` 不控制所有报告写入者。核对 Harness、修复任务和执行器各自路径；完整输出与展示摘要分别保存。控制实验的空报告是注入反例，不表示默认 Harness 会正常产生空绿灯。

## 一次远程运行有多种身份

PR 头是候选分支状态；实际 checkout 可能是平台产生的合并测试提交。Run ID 与 attempt 区分运行及重试，工作流版本确定执行规则，报告哈希绑定下载后原始字节。这些字段各自有来源，模拟生成的信封不能证明真实平台运行。归档成功只说明文件被上传，不能证明业务通过。

源文件相同仍不足以声称实验条件相同：解释器、依赖、数据初始化、服务入口和用例发现也会改变结论。A/B 固定业务和检查，B/C 固定检查与工作流；缺报告、进程提前退出、执行器丢失分别留原原因，不能引用旧 artifact 填补。

## 课程快捷命令与个人冻结候选

`course-submit --lesson 8 --execute-code` 是课程通用合同的快捷路线，会从课程标签创建新的 Worktree，不自动带入另一个候选的未提交检查；标签与组合快照的来源也不同。当前 `--requirement-spec` 的实现仅接受 L04、L15/L16，不能将它传给 L08。需要比较同案 A/B/C 时，主手册采用 `course-prepare --source working-tree` 后绑定该候选的 task-create/task-run，先冻结个人 Spec 与检查，再分阶段授权。两条方式不能交叉冒充同一候选的证据。

# CI 候选证据审查

先确定本次复核阶段：本地机制实验、产品修复、CI 接线或远程交付。接受该阶段的任务要求、候选身份、工作流、报告和实际进程结果。远程交付从平台记录定位运行；本地实验按其实际范围判断，不因没有远程记录而否定实验价值，也不把本地通过升级为远程通过。

1. 核对事件、分支头、实际 checkout SHA、Run ID、attempt 与工作流。PR 合并测试与分支头测试语义不同，先确认预期对象，不把 SHA 不同一律判伪。
2. 根据任务确定必需用例与等级，再核对实际报告。全套选择与显式子集的规则按当前 Harness 实现处理；不能把报告自报集合反当需求。
3. 分别判断检查退出、步骤/Job 结果和归档结果。上传成功不能覆盖业务失败，continue-on-error 或外层吞码须保留矛盾。
4. 重算下载后原始报告的哈希，不混用压缩包摘要。核对本次输出与目录、attempt 的关系；缺报告、崩溃和旧信封不能借历史通过补位。
5. 区分参考服务、教学断言、本地模拟身份与真实远程运行。L08 原子性须观察多行和失败后的完整相关状态，单行缺货不足以证明中途写入回滚。

做 A/B/C 因果复核时，先确认 A 与 B 的产品内容相同，再确认三次检查未被削弱；A 到 B 只支持失败传播恢复，B 到 C 才能支持所测业务恢复。检查实际外层进程与内部 Harness 的各自退出码，不能只读人为填写的摘要。

输出“要求—证据—已证实/矛盾/缺失—下一步”。提供有限接受建议，不把本流程当发布或合并授权。缺证据时继续核对已有材料，不猜造平台记录或同伴签名。用户授权修复时保留原始失败并在范围内修改，不降低标准凑通过。

验证流程时读取[反例](references/review-cases.md)，保存真实响应与漏判；参考判断不算运行记录。

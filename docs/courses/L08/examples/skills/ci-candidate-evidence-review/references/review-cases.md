# CI 审查反例

以下是构造输入，用于检验判断，不是远程运行记录。

## A：上传成功

Harness 返回 1、报告 block。上传步骤成功，提交者写“artifact 已上传，候选通过”。应识别传输与业务结果不同，查看 Job 是否正确失败，不能给出接受结论。

## B：两个提交身份

PR 头为 H，平台 pull_request 合并测试实际 checkout 为 M，报告关联 M。提交者声称“SHA 不同，所以报告伪造”。应先核对事件和合并语义：如果任务要求验证合并结果，差异本身合理；若要求只测 H，需要针对 H 的运行。不能无条件接受或拒绝。

## C：旧信封

本次缺报告，信封命令返回 1，但旧路径仍有上次 pass 的文件。提交者只提供文件存在截图。应识别本次未验证，索取当前 attempt 的结果和日志，不能改写旧文件冒充新记录。

## D：完整材料

使用练习者真实取得的一套 A/B/C、候选身份、下载报告、哈希、退出和同伴复核。应依据实际覆盖给出有限结论，不为套用反例而一律拒绝。尚无真实材料时保留此项待验证。

## E：实际产品 A/B/C

[本地原始索引](../../../../assets/latest/product-abc-index.json)中，A 与 B 使用同一份提前提交的业务缺陷，C 恢复完整事务；三组检查内容相同。实际内部/外层退出依次为 1/0、1/1、0/0。应识别 A 为吞错、B 为正确报出仍存在的缺陷、C 为原检查接受产品修复。材料证明本地进程和产品行为，尚不证明远程 Job 或人工接受。审查者若只因没有远程链接而否认全部实验，或者直接认定远程交付成功，都属于判断越界。

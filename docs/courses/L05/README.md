# L05｜先设计失败，再编写 Eval

承接 L04 已建成的工作台 V0。本讲以重复收货为现场问题，先建设能识别错误的业务与工程 Eval，再由工作台组织 Codex 构建或修复 FlowERP 幂等入库。

1. [辅导资料](辅导资料.md)：从现有绿灯的遗漏推导检查与反例。
2. [实践操作手册](实践操作手册.md)：同一事项的设计、两次失败、候选修复和原生界面核查。
3. [行动卡](行动卡.md)与[分阶段提示词](prompts/README.md)：落实本人判断和同伴复验。
4. [failure-first-eval skill](skills/failure-first-eval/SKILL.md)：按实际阶段采用流程，含反例练习。
5. [课堂 PPT](slides/L05-先设计失败再编写Eval-讲义同步版-30页.pptx)：30 页，与现行讲义同步；7 个编号案例，包含两条实验路径、流水字段与完整状态诊断、真实范围检查、工作台交付和总结思考题。

记录直接保存在已有事项、任务与命令证据中。参考实验使用临时数据库和临时仓库，不能代替个人产品修复或具名接受。截图与执行来源见 [证据说明](assets/README.md)。

实践手册现提供 Windows PowerShell 连续命令、会话恢复、独立工程练习仓库、可运行检查支架、按文件提交以及最终候选的范围和指纹复验。每次调用记录完整目录、命令、退出码和输出，保留重复实验的旧证据。支架不是个人学习成果，实际构建、补充检查和独立审核仍需分别完成。

配套资料：[辅导资料](辅导资料.md)、[实践操作手册](实践操作手册.md)，可按需查阅。

命令实测结果、保留的失败和适用环境见[命令复验说明](命令复验说明.md)。

新版先读：FlowERP 项目定位、业务流程、两套系统架构与 FDE 推动工作台升级的因果关系。

案例重点：旧检查为什么漏掉重复流水、两次失败如何证明检查有效、保持检查修复、真实差异约束、最终候选与独立迁移。课堂夹具与正式课程候选分别说明，具体页码见讲义和手册的案例索引。

# 阶段执行与证据核对

## 设计检查

读取实际 AGENTS、L05 合同、候选入库实现与现有用例。用当前源码指出“已覆盖、未覆盖、尚未确认”，不能凭函数名推断。让人的业务决定先于断言：首次、新请求、重试、非法数量以及失败后状态分别观察什么。失败信息包含要求编号、预期与实际。

## 验证检查

保持同一缺陷版本和检查版本连续运行两次。各次独立临时数据，保存命令、目录、实际加载模块、退出码、时间和输出。模块错误、零测试、门闩红灯另行处理。教学注入说明位置与机制，不能伪称产品事故。至少一个正常新请求和一个合法工程修改应通过，避免把全部拒绝误当可靠。

## 保存会话基线

当前课程执行器要求默认 receiving_is_idempotent 在起点失败。个人新增用例红、默认用例绿时先核对真实缺口，不能用环境错误或修改控制门闩满足前置检查。

L05 course-submit 创建新的隔离候选，不会自动携带另一个工作区的未提交检查。先在课程准备候选中保存包含新增检查的缺陷提交，在控制仓库确认可解析且位于课程起始标签之后，再用 --session-baseline-ref 引用。具体入口见[实践操作手册](../../../../实践操作手册.md)第5、6节。不要给 L05 传 L04 的 --requirement-spec 参数。

## 最小修复与范围

已授权后持续完成同案最小修复，不重复索要同一授权。新增写集或改变业务承诺时先说明实质变化。业务观察读持久化库存与完整流水；工程观察读候选相对基线的实际差异。授权清单来自执行前决定，检查方保存。重命名核对旧新路径，未跟踪文件不可遗漏。轻量 Git 示例不覆盖被忽略文件、已撤销写入、仓库外写入和子模块内部差异，不能当运行时沙箱。

## 回到工作台

核对交付任务、候选、检查版本及默认报告覆盖。新增用例若只单独运行，单列原始输出，不能声称已进入网页报告。CLI任务未自动绑定首页事项时明确记录双方编号和证据路径，不改数据库伪造关联。

## 交接

比较原红灯与修复后同命令结果，并单独看检查文件的 Diff。删除断言、改业务期望或换被测模块得到的绿灯不足以证明修复。确需修订检查时保留理由与旧版，重建反例。实际复验者在同一候选变换输入、核对失败后状态并具名决定。未复验的事项保留待完成。

## 完整采用示例

输入：当前为独立复验；候选已经明确；检查与基线已给定；只读验证；期初11、收货3。

先预测库存11、14、14、17，流水1、2、2、3。核查实际加载模块属于给定候选，比较检查指纹，再运行原检查与换输入检查。若发现检查被删断言，则回到检查建设；若只是环境导入失败，则修正验证入口，不把它记录成业务反例。输出注明亲自运行、历史记录与待验证项。

# L12｜用 Graph 显式表达状态、回退和人工审核

L11 已把采购申请保存下来。现在要交付“批准后才能收货”，软件检查通过后却还要等审核人，打回后要重新修改，重启后还要知道上次停在哪版。**本讲把这些去向写成可执行的状态图；FlowERP 在具名采购批准和真实收货之后，才增加库存。**

![候选 X 等待审核，被打回形成 Y 后重新检查再送审](assets/reading-story-20260926/01-wait-return.png)

从左到右看同一研发任务：X 检查通过后等待人；打回保留理由；Y 是新候选，需要新的检查。下方提示说明旧报告为什么不能沿用。图为教学示意。

[L11](../L11/README.md) 决定工作怎样分给两条独立支路，本讲决定整体下一步去哪里；[L13](../L13/README.md) 再让离开终端的人凭原编号查到这些已保存事实。

## 按这条路线学习

1. [辅导资料](辅导资料.md)：先看“审核人明天才来”，理解等待、打回、候选绑定与恢复，再分清软件验收和采购批准。
2. [实践操作手册](实践操作手册.md#lesson-goals)：观察三个独立实验，再实现自己的状态转移、保存和具名决定，核对采购单、库存与流水。
3. [提交模板](SUBMISSION.md)：保留实际经过的路线、非法路线拒绝、审核理由、重启与同键收货结果。

**本讲动作线：**申请已存在 → 软件候选开发与检查 → 等待或打回 → 具名接受软件 → 采购负责人批准单据 → 实际收货与对账。

# L00｜课前准备：装好工具，跑通第一次环境自检

**L00 从一个没有任何代码的空目录开始，用 Codex 建成可运行的个人 AI 研发工作台基础版 V0.0。** 它能登记事项、查看记录、保存处理结果，并在重启后查回；后面的讲次逐步优化它，FlowERP 在 L04 首次接入。

本手册先帮你准备工具，再转入[从 0 开始搭建个人 AI 研发工作台](./从0开始搭建个人AI研发工作台.md)完成建设。主线是：**装好工具 → 建空项目 → 确认需求 → 生成源码 → 启动与检查 → 留下基础版。**

开始时可以用记事本或 macOS“文本编辑”的纯文本模式记录工具版本与错误。项目建立后，将[提交模板](../labs/L00/SUBMISSION.md)另存到自己的项目：`lesson-00-submission/L00-环境自检.md`，转入临时记录，边做边填写真实结果。

## 开始前：选对操作位置

终端执行命令，VS Code 查看文件和写记录，Codex 对话框接收自然语言任务。只有明确到建设步骤时，才授权 Codex 生成源码。

- **Windows：**打开 PowerShell，使用 Windows 命令块。
- **macOS：**按 `Command+空格`搜索“终端”，使用 zsh 命令块。可运行 `zsh --version`查看版本；当前用 bash 时，先运行 `zsh`进入 zsh。

只复制代码框中的命令，不复制代码标签或终端行首的 `%`、`$`。命令逐行执行，核对预期后再继续；退出码那一行紧接被检查的命令执行。路径有空格或中文时，用英文双引号包住。停止服务按 `Ctrl+C`（Mac 为 `Control+C`）。

## 1. 装好四个工具

已经安装的工具，先检查版本，不必重复安装。下载安装和 Codex 登录需要网络；本讲不要求 Homebrew、Node.js、Docker 或本地大模型。

### Python：统一使用 3.11.x

**Windows，终端命令：**

```powershell
py -3.11 --version
```

找不到时，按 [Python 官方 Windows 说明](https://docs.python.org/3/using/windows.html)安装 Python Install Manager，重开 PowerShell，再运行：

```powershell
pymanager install 3.11
py -3.11 --version
```

**macOS，终端命令：**

```zsh
python3.11 --version
```

找不到时，从 [Python 3.11.9 发布页](https://www.python.org/downloads/release/python-3119/)下载 **macOS 64-bit universal2 installer**，安装后重开终端再检查。这里指定 `python3.11`，避免 `python3` 指向其他版本。

**完成判断：**看到 `Python 3.11.x`，把完整版本写入记录。

### Git：能在终端执行

**两种系统通用，终端命令：**

```text
git --version
```

找不到时，Windows 安装 [Git for Windows](https://git-scm.com/install/windows)；Mac 按 [Git 官方 macOS 说明](https://git-scm.com/install/mac)安装，也可能由系统提示安装 Apple 命令行工具。安装后重开终端。

**完成判断：**看到 `git version ...`，记录版本。

### VS Code：能打开文件，选 Python 解释器

从 [VS Code 官方下载页](https://code.visualstudio.com/Download)安装稳定版。Mac 可选 Universal 包，将 `Visual Studio Code.app` 放入“应用程序”后打开。

在 VS Code 左侧“扩展”中搜索 `ms-python.python`，确认发布者为 Microsoft，再安装。

**Mac 还要配置终端入口：**按 `Command+Shift+P`，运行 `Shell Command: Install 'code' command in PATH`，然后重开终端。操作依据：[VS Code 官方 macOS 说明](https://code.visualstudio.com/docs/setup/mac)。

**两种系统通用，终端命令：**

```text
code --version
```

**完成判断：**记录实际版本。若 `code` 暂不可用但应用能打开，可先用菜单继续：Windows 从“帮助 → 关于”、Mac 从“Code → About Visual Studio Code”查看版本，并记下这项问题。

### Codex：准备 CLI 和可用的桌面入口

按 [OpenAI 官方桌面说明](https://learn.chatgpt.com/docs/app)安装应用，用自己的 ChatGPT 账号登录并选择 Codex；再按 [CLI 安装说明](https://learn.chatgpt.com/docs/codex/cli)安装终端入口。

**Mac 没有 CLI 时，在 zsh 运行：**

```zsh
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

按安装器输出处理 PATH，并重开终端。

**两种系统通用，终端命令：**

```text
codex --version
```

**完成判断：**CLI 能显示版本。登录与实际提问在建设手册第 2 步验证。

官方 Mac 桌面下载当前标注 Apple Silicon。Intel Mac 或系统版本不兼容时，记录“桌面入口不适用”及原因，使用 CLI 完成同一实践，保留相同的人工核验要求。安装说明核对日期：2026-10-03。

## 2. 从空目录建成基础工作台

工具可用后，打开[从 0 开始搭建个人 AI 研发工作台](./从0开始搭建个人AI研发工作台.md)，从第 1 步顺序执行：

| 建设步骤 | 你应得到什么 |
|---|---|
| 1. 创建空目录和环境 | 起点没有源码，Python 来自自己项目的 `.venv` |
| 2. 确认需求 | 自己确认的 `WORKBENCH_SPEC.md` |
| 3. Codex 生成源码 | 实际保存的 `app.py`、说明和忽略规则，语法检查通过 |
| 4. 启动程序 | 本项目提供的 V0.0 首页 |
| 5. 四项现场检查 | 新建与查询、空标题拒绝、结果与状态、重启恢复均已核对 |
| 6. 保留基础版 | 源码、需求、真实检查记录和未解决问题 |

L00 的项目独立从空目录建立。课程资料用于指导，不需要克隆课程程序、导入 `workbench` 包、运行课程的 `serve` 或执行 `pip install -e .`。工作台代码应由本次建设产生。

每完成一步再进入下一步。若 Codex 宣布“已完成”，先看实际文件和自己的运行结果；它的说明不能代替现场检查。第 5 步还要亲自核对 Codex 引用的两个程序行为：任务怎样保存、重启后从哪里读回。

## 3. 保存记录，判断是否完成

在自己的项目中填写 `lesson-00-submission/L00-环境自检.md`。记录应包含工具版本、空目录起点、解释器路径、需求决定、生成文件、启动命令、四项检查、两项文件核验，以及失败与修复。没有完成的项如实标注。

| 状态 | 判断依据 |
|---|---|
| 基础版完成 | 自己的新项目能运行；四项现场检查通过；已核对两个文件依据；记录可重新打开 |
| 需要辅导 | 程序能启动，但某项检查、核验或解释未完成，写明停在哪一步 |
| 环境受阻 | 安装、登录或解释器导致无法继续，保存真实错误与尝试 |

保留完整项目用于后续建设。提交时按开营通知提供源码、需求和个人记录，不附 `.venv`、运行数据库或凭据。

## 4. 带着这一版继续建设

后续课程的任务是逐讲补能力。带上三样东西：**V0.0 源码、自己的需求与检查记录、一个使用中发现的问题。** 例如：“能把状态改成已完成，但我还没有可靠办法证明工作已经做对。”

下一步应围绕这个问题增强需求、证据和复验，再逐步加入规则、解析与受控执行。基础版成果要保留；后续材料的起点与迁移操作须与这份成果对齐，不能用新的一份现成程序替代自己的建设记录。

## 遇到问题再看

### 先定位错误

| 现象 | 最小检查与下一步 |
|---|---|
| `py -3.11` / `python3.11` 找不到 | 确认 3.11 已安装，重开终端，再查版本 |
| 提示目标目录已存在 | 换一个新的项目名称；续做则回到原项目，不覆盖旧文件 |
| `.venv` 的 Python 找不到 | 核对当前目录和记录中的项目路径，再检查环境是否创建成功 |
| `app.py` 找不到 | 核对当前目录与 Codex 实际写入位置；未生成文件则回到建设步骤 3 |
| 语法检查失败 | 保存完整错误，让 Codex 修复后，用原命令重新检查 |
| 端口被占用 | 保留错误，用 `--port 8002`启动并访问对应根路径，不结束其他进程 |
| 页面能开但记录丢失 | 核对数据文件位置和重启初始化逻辑；保留原数据，修复后再验 |
| Mac 的 `code` 找不到 | 用 VS Code“文件 → 打开文件夹”，按第 1 步配置命令入口 |
| `codex` 找不到或登录失败 | 核对安装器输出与 PATH，Mac 可运行 `rehash`、`command -v codex`；保留错误 |
| PowerShell 显示 `>>`，Mac 显示 `quote>` / `dquote>` | 按 `Ctrl+C` / `Control+C`取消，重新复制完整命令 |

### 重开终端后怎样继续

先回到记录中的项目绝对路径。下面使用默认路径；如果你另选了名称或位置，替换第一行。

**Windows PowerShell：**

```powershell
Set-Location "$env:USERPROFILE\work\my-ai-workbench"
.\.venv\Scripts\python.exe --version
```

**macOS zsh：**

```zsh
cd "$HOME/work/my-ai-workbench"
.venv/bin/python --version
```

应看到 Python 3.11.x。接着从上一次未完成的建设步骤继续。已经建好的环境不用重建；虚拟环境不能在 Windows 与 macOS 之间直接复制。

### 带着事实求助

把下面内容发给 Codex，请它先解释，只给一个最小检查步骤；仍无法解决时，将同一记录发给老师。

```text
我在完成 L00 建设步骤__，请先解释错误，不删除已有源码或数据。
只给一个最小检查步骤，说明操作位置与预期结果。
操作系统和终端：
当前项目目录：
实际命令或页面动作：
完整输出、退出码或页面现象：
预期结果：
已经尝试的动作：
需要帮助确认的问题：
```

发送前遮盖凭据和私人信息，保留命令与原始错误。

# L00｜课前准备：装好工具，跑通第一次环境自检

## 你今天要完成什么

这一讲只做环境准备，不写工作台，不开发 FlowERP。

你要按顺序完成 8 件事：

1. 建立一份自检记录。
2. 安装并检查 Python、Git、VS Code 和 Codex。
3. 下载课程仓库。
4. 在仓库内创建 `.venv`。
5. 用 VS Code 打开课程工作区。
6. 运行环境自检。
7. 让 Codex 给出文件证据，你亲自核对其中两处。
8. 完成四个小练习，保存提交物。

最后应得到这个文件：

```text
lesson-00-submission/L00-环境自检.md
```

没有完成的项目可以写“未完成”或“尚未确认”。不要猜测结果，也不要复制别人的结果。

|---|---|

本手册分别给出 Windows 和 macOS 命令。只做自己系统的那一组。

## 第 2 步：安装并检查四个工具

### 2.1 Python 3.11

课堂统一使用 Python 3.11.x。

#### Windows

先在 PowerShell 运行：

```powershell
py -3.11 --version
```

如果看到以 `Python 3.11` 开头的版本，记录版本，继续下一项。

如果找不到 Python 3.11，按 [Python 官方 Windows 说明](https://docs.python.org/3/using/windows.html)安装 Python Install Manager，重新打开 PowerShell，再运行：

```powershell
pymanager install 3.11
py -3.11 --version
```

#### macOS

在 Terminal 运行：

```bash
python3.11 --version
```

如果看到以 `Python 3.11` 开头的版本，记录版本，继续下一项。

如果找不到，从 [Python 3.11.9 发布页](https://www.python.org/downloads/release/python-3119/)下载 **macOS 64-bit universal2 installer**。安装后重新打开 Terminal，再运行上面的版本命令。

### 2.2 Git

运行：

```text
git --version
```

应看到类似 `git version 2.x.x` 的输出。

如果找不到 Git：

- Windows：从 [Git for Windows](https://git-scm.com/install/windows)下载并安装。
- macOS：按 [Git 官方 macOS 说明](https://git-scm.com/install/mac)安装；系统也可能提示安装 Apple 命令行工具。

安装后重新打开终端，再运行 `git --version`。

### 2.3 Visual Studio Code

从 [VS Code 官方下载页](https://code.visualstudio.com/Download)安装当前稳定版。

打开 VS Code，再安装 Microsoft 发布的 Python 扩展：

1. 点击左侧“扩展”。
2. 搜索 `ms-python.python`。
3. 确认发布者是 Microsoft。
4. 点击“安装”。

再在终端运行：

```text
code --version
```

如果这条命令失败，但 VS Code 能从图标打开，可以先在“帮助 → 关于”中查看版本，并在记录中写明 `code` 命令尚不可用。

### 2.4 Codex

准备两个入口：

1. 安装 Codex 桌面应用，用自己的 ChatGPT 账号登录。
2. 按 [Codex CLI 官方安装说明](https://learn.chatgpt.com/zh-Hans/docs/codex/cli)安装命令行入口。

安装后在终端运行：

```text
codex --version
```

应该看到 Codex CLI 版本。只打开登录页不算完成；第 7 步还要实际发出一次只读问题。

### 这一步完成后

自检记录中应有：

- Python 的完整版本。
- Git 版本。
- VS Code 版本。
- Codex CLI 版本。
- Codex 桌面入口能否登录。

某一项失败时，把命令和完整报错保存下来，再查本文末尾的“常见问题”。

## 第 3 步：下载课程仓库

选择一个你有写入权限、不会自动同步到网盘的目录。

### Windows

在 PowerShell 中逐行运行：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\work"
Set-Location "$env:USERPROFILE\work"
git clone https://github.com/congde/CodexFDE.git
Set-Location CodexFDE
git status
```

### macOS

在 Terminal 中逐行运行：

```bash
mkdir -p ~/work
cd ~/work
git clone https://github.com/congde/CodexFDE.git
cd CodexFDE
git status
```

### 你应该看到什么

`git status` 应能识别当前仓库，不应出现 `not a git repository`。

再用文件管理器或 VS Code 确认根目录中有：

```text
pyproject.toml
AGENTS.md
docs
```

如果 `git clone` 提示同名目录已存在，先进入该目录运行 `git status`，确认它是不是已经下载好的课程仓库。不要直接删除现有目录。

不要用“下载 ZIP”代替正常克隆；后续课程要使用 Git 历史和文件差异。

### 设置本仓库的学习身份

先查看当前设置：

```text
git config user.name
git config user.email
```

如果为空，或不是你准备使用的学习身份，再运行：

```text
git config --local user.name "你的学习署名"
git config --local user.email "你的邮箱"
```

将引号中的文字替换为自己的信息。`--local` 表示只修改当前课程仓库。

## 第 4 步：创建课程虚拟环境

虚拟环境 `.venv` 是这个课程专用的 Python 环境。后面的课程命令都使用它，不使用系统 Python 代替。

运行前，先确认当前目录中能看到 `pyproject.toml`。

### Windows

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe --version
```

### macOS

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -e .
.venv/bin/python --version
```

每行成功后再运行下一行。最后应看到 `Python 3.11.x`。

如果看到 `not a Python project`，通常表示当前不在有 `pyproject.toml` 的课程根目录。

如果仓库中已经有 `.venv`，先运行最后一条版本命令。版本不是 3.11.x 时，不要直接覆盖；记录路径和版本，再请老师帮助确认是否重建。

## 第 5 步：用 VS Code 打开课程工作区

在 VS Code 中选择“文件 → 从文件打开工作区”，打开：

```text
docs/courses/FlowERP-AI研发工作台.code-workspace
```

## 第 6 步：运行环境自检

先确认新终端位于课程根目录。然后只运行自己系统的那组命令。

### Windows

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "import sys, sqlite3; print(sys.version); print(sys.executable); print('sqlite', sqlite3.sqlite_version)"
$LASTEXITCODE
.\.venv\Scripts\python.exe -X utf8 -c "import workbench, eval; print('imports-ok')"
$LASTEXITCODE
.\.venv\Scripts\python.exe -X utf8 -m workbench.cli --help
$LASTEXITCODE
git status --short
git diff --stat
```

### macOS

```bash
.venv/bin/python -X utf8 -c "import sys, sqlite3; print(sys.version); print(sys.executable); print('sqlite', sqlite3.sqlite_version)"
echo $?
.venv/bin/python -X utf8 -c "import workbench, eval; print('imports-ok')"
echo $?
.venv/bin/python -X utf8 -m workbench.cli --help
echo $?
git status --short
git diff --stat
```

### 逐项核对

| 你应看到 | 它证明什么 |
|---|---|
| Python 版本为 3.11.x | 课堂版本正确 |
| 解释器路径包含当前仓库的 `.venv` | 实际使用的是课程环境 |
| `imports-ok` | `workbench` 和 `eval` 包可以被找到 |
| `workbench.cli` 帮助文本 | 命令入口可以加载 |
| 退出码为 0 | 紧邻的那条命令成功 |

`git status --short` 和 `git diff --stat` 没有输出不一定是问题。在记录中明确写“无输出”，不要伪造一段输出。

如果出现 `ModuleNotFoundError`，先检查三件事：

1. 当前是否在课程根目录。
2. 运行命令的 Python 路径是否在当前仓库的 `.venv` 中。
3. 第 4 步的 `pip install -e .` 是否成功结束。

本讲不启动 Web 服务，不运行 `serve`、`demo`、`course-status`、全量测试或 blocking Eval。这些结果也不能代替 L00 自检。

## 第 8 步：完成四个小练习

### 练习 1：确认自己在哪里

Windows：

```powershell
Get-Location
Get-ChildItem -Name
```

macOS：

```bash
pwd
ls
```

在输出中找到 `pyproject.toml` 和 `docs`。然后在 VS Code 中打开 `pyproject.toml`，找到 `requires-python`。

在记录中回答：

- 仓库允许的 Python 最低版本是什么？
- 本班统一使用的版本是什么？

两者不同：仓库最低支持 Python 3.10，本班统一使用 Python 3.11.x。

### 练习 2：先预测，再运行

先不运行命令，回答：20 件商品中，8 件已留给客户，还能再卖多少件？

写下预测后，再运行：

Windows：

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "print(20 - 8)"
```

macOS：

```bash
.venv/bin/python -X utf8 -c "print(20 - 8)"
```

应输出 `12`。把预测和实际结果都写入记录。

再回答：这条命令只检查了一道算式，能不能证明 FlowERP 的库存功能已经完成？

答案是不能。它没有检查真实订单、数据存储或重复操作。

### 练习 3：认识“预期中的失败”

先预测下面的检查会成功还是失败。

Windows：

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "available = 13; assert available == 12"
$LASTEXITCODE
```

macOS：

```bash
.venv/bin/python -X utf8 -c "available = 13; assert available == 12"
echo $?
```

预期结果是 `AssertionError`，退出码为非 0。这是故意造成的失败，不表示电脑坏了。

保存失败记录后，再运行修正后的计算：

Windows：

```powershell
.\.venv\Scripts\python.exe -X utf8 -c "available = 20 - 8; assert available == 12"
$LASTEXITCODE
```

macOS：

```bash
.venv/bin/python -X utf8 -c "available = 20 - 8; assert available == 12"
echo $?
```

这次应没有正文输出，退出码为 0。

在记录中说明：改动的是计算，保持不变的是检查要求 `available == 12`。

### 练习 4：理解检查范围

回到第 7 步的 Codex 回答，填好两条人工核验记录。

然后回答：Codex 说“文件已修改”，但 `git diff` 没有输出，是否一定表示没有修改？

答案是不一定。新建的未跟踪文件不会出现在普通 `git diff` 中。还要运行：

```text
git status --short
```

`??` 表示未跟踪的新文件，`M` 表示文件已修改。

### 变化题

现在有 30 件商品，9 件已留给客户。

1. 先写下你的预测。
2. 仿照练习 2，用 `.venv` 中的 Python 运行算式。
3. 保存实际输出。
4. 回答：如果终端找不到 `.venv` 中的 Python，你先检查什么？如果 Python 已经执行，但出现 `AssertionError`，你又先检查什么？

先自己回答，不要让 Codex 代写首次判断。

## 常见问题

| 看到的现象 | 先检查什么 | 下一个动作 |
|---|---|---|
| `py -3.11` 或 `python3.11` 找不到 | Python 3.11 是否真正安装完成 | 重新打开终端，再查版本 |
| `.venv` 中的 Python 找不到 | 当前目录是否有 `pyproject.toml` 和 `.venv` | 回到课程根目录；未创建则重做第 4 步 |
| `not a Python project` | 当前目录和命令末尾的 `.` | 进入有 `pyproject.toml` 的目录再运行 |
| `ModuleNotFoundError` | 安装和运行是否用了同一个 `.venv` | 重新核对解释器路径和 `pip install -e .` |
| `not a git repository` | 是否还在 `work` 父目录 | 进入真正的 `CodexFDE` 目录；不要用 `git init` 冒充克隆 |
| 克隆提示目录已存在 | 是否以前已经下载过 | 进入现有目录运行 `git status`，不要直接删除 |
| `code` 找不到 | VS Code 能否从图标打开 | 先记录“关于”中的版本，再处理 PATH |
| `codex` 找不到 | Codex CLI 是否安装，终端是否重开 | 按官方 CLI 页面重新核对安装方式 |
| PowerShell 显示 `>>` | 是否漏了引号或误复制多行 | 按 `Ctrl+C` 取消，重新复制一条完整命令 |
| macOS 显示 `quote>` 或 `dquote>` | 引号是否成对 | 按 `Control+C` 取消，重新复制完整命令 |
| 练习 3 出现 `AssertionError` | 是否正在运行故意失败的第一条命令 | 保存失败证据，继续运行修正后的命令 |
| 网络超时或 Codex 登录失败 | 是下载问题还是账号问题 | 保留完整报错，按下面模板求助 |

不要为了排错而关闭安全软件、修改整机执行策略、删除现有作业或扩大 Codex 权限。

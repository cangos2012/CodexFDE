# 从 0 开始搭建个人 AI 研发工作台

**L00 的起点是一个空文件夹，没有任何程序代码；终点是你用 Codex 建成、亲自运行和检查的基础工作台 V0.0。** 后面的讲次围绕这版工作台逐步优化。

这次只完成一条小闭环：**打开工作台 → 写下一件要做的事 → 记录处理结果 → 重启后查回。** 先把这条路走通，再增加更复杂的能力。

## 你将造出什么

基础版运行在本机，浏览器打开 `http://127.0.0.1:8001/`。首页显示“个人 AI 研发工作台 V0.0”，从“事项与决策”开始工作。

| 你在页面上的动作 | 程序应做到什么 |
|---|---|
| 新建一项任务，填写标题、目标和完成条件 | 保存任务，给它一个编号，初始状态为“待处理” |
| 查看任务列表、打开任务 | 能查回自己输入的内容 |
| 填写实际处理结果，选择“处理中”或“已完成” | 保存结果和你选择的状态，不自行宣布完成 |
| 停止程序，再启动 | 原任务、结果和状态仍在 |

例如，你可以登记“核对下周课程时间”，写明“找到通知中的日期并人工核对”这个完成条件。实际核对后，再填写结果。示例只用来理解操作；练习时换成你自己的一件小事。

这一版由你在工作台登记任务，再与 Codex 对话完成工作，最后把真实结果记回来。自动调用 Codex、限制代码改动、统一测试与人审，将在后续讲次逐步加入。

## 1. 从真正的空目录开始

先按[工具准备手册](./L00｜课前准备：装好工具，跑通第一次环境自检.md#1-装好四个工具)装好 Python 3.11、Git、VS Code 和 Codex，再回到这里。

选择一个有写入权限的本地目录。下面用用户目录下的 `work/my-ai-workbench`；已有同名目录时，换一个新的名称，不删除或覆盖旧项目。**本步骤不克隆课程仓库、不下载成品工作台，也不复制课程源码。**

**Windows PowerShell，终端命令：**

```powershell
& {
    $ErrorActionPreference = 'Stop'
    $workbenchFolder = Join-Path $env:USERPROFILE 'work\my-ai-workbench'
    if (Test-Path -LiteralPath $workbenchFolder) {
        throw '目标目录已存在，请换一个新的目录名称，不覆盖已有内容。'
    }
    New-Item -ItemType Directory -Path $workbenchFolder | Out-Null
    Set-Location -LiteralPath $workbenchFolder
    Get-Location
    Get-ChildItem -Force
}
```

**macOS zsh，终端命令：**

```zsh
create_workbench_folder() {
  local workbenchFolder="$HOME/work/my-ai-workbench"
  if [ -e "$workbenchFolder" ]; then
    printf '目标目录已存在，请换一个新的目录名称，不覆盖已有内容。\n'
    return 1
  fi
  mkdir -p "$workbenchFolder" || return 1
  cd "$workbenchFolder" || return 1
  pwd
  ls -A
}
create_workbench_folder
```

预期：显示新目录的绝对路径，文件列表为空。把路径和这个起点记下来。若出现文件，先确认是否进入了其他项目；不要继续覆盖。

接着在同一个终端创建本项目的 Python 环境，并让 Git 识别这个新项目。

**Windows PowerShell：**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -X utf8 -c "import sys, sqlite3; print(sys.version); print(sys.executable); print('sqlite', sqlite3.sqlite_version)"
$LASTEXITCODE
git init
git status --short
```

**macOS zsh：**

```zsh
python3.11 -m venv .venv
.venv/bin/python -X utf8 -c "import sys, sqlite3; print(sys.version); print(sys.executable); print('sqlite', sqlite3.sqlite_version)"
echo $?
git init
git status --short
```

逐行运行，前一条失败先排查，不继续下一条。预期 Python 为 3.11.x，解释器属于当前项目的 `.venv`，SQLite 能导入，检查退出码为 `0`。Git 此时可能显示 `.venv/` 未跟踪；稍后用 `.gitignore` 排除它，不要提交。

现在出现的 `.venv` 和 `.git` 是运行环境与版本管理目录，工作台源码仍为零。这里没有 `pyproject.toml`、`workbench` 包或可安装的课程程序，因此无需执行 `pip install -e .`。

**完成判断：**你能指出自己的空项目起点和专用 Python 路径，没有借用另一份工作台实现。

## 2. 打开这个目录，先把第一版需求说清楚

在 VS Code 选择“文件 → 打开文件夹”，打开刚才的目录。也可在当前终端运行两端通用命令 `code .`；命令不可用时直接使用菜单。

在 Codex 桌面入口中打开**同一个新目录**，或在这个目录的终端运行 `codex` 并按提示登录。终端切换目录，不代表另一个 Codex 任务已经切换；先核对它实际使用的位置。

**发送给 Codex 的第一条消息：**

```text
我要从这个空目录搭建个人 AI 研发工作台基础版 V0.0。
请先只读列出当前目录，确认没有工作台源码；不要寻找或复制课程仓库的实现。
先帮助我确认第一版需求，不要立即写代码。每轮只问一个主要问题，等我回答。
基础操作是：登记事项、查看事项、记录实际处理结果、重启后查回。
请先问我希望用这版工作台管理哪一件真实的小事。
```

逐轮确认要管理什么、需要保存哪些信息、怎样判断记录成功。你确认的完成条件要能现场检查，例如“关闭程序再启动，仍能查到刚才输入的结果”。

确认后，让 Codex 将结论写成项目根目录的 `WORKBENCH_SPEC.md`，暂不写程序。你在 VS Code 打开并核对下面几件事，再填写自己的确认日期与学习署名：

- 本次目标和明确暂缓的能力。
- 事项的标题、目标、完成条件、实际结果和状态。
- 空标题被拒绝，而且不会多出一条任务。
- 数据保存在本项目内，重启后仍可查回。
- 只有本人选择“已完成”，程序才保存该状态。

这时新目录里有了第一份需求文档，但仍然没有程序代码。

**完成判断：**你能解释第一版解决什么问题，并已确认它的完成条件。

## 3. 让 Codex 生成第一批源码

现在才进入建设。**在同一个 Codex 对话中发送：**

```text
请依据我刚确认的 WORKBENCH_SPEC.md，在当前新项目中从零实现基础版 V0.0。

技术要求：
1. 使用 Python 3.11 标准库，采用 http.server、sqlite3 等本机能力，不安装第三方库。
2. 创建 app.py、README.md 和 .gitignore，不导入课程仓库或其他项目的源码。
3. 使用 python app.py 启动，默认只监听 127.0.0.1:8001；支持 --port 指定端口。
4. 首页根路径 / 显示“个人 AI 研发工作台 V0.0”，从“事项与决策”登记任务。
5. 新建任务保存标题、目标、完成条件、编号和创建时间；初始状态为“待处理”。
6. 能查看任务，保存实际处理结果，并由人选择“待处理”“处理中”或“已完成”。
7. 用 SQLite 将数据存入项目根目录下的 .runtime/workbench.db，启动时保留已有记录。
8. 空白标题给出明确提示且不新增记录；未知任务不能改动已有任务。
9. SQL 参数化；页面显示用户输入时做 HTML 转义；表单提交后回到页面。
10. .gitignore 排除 .venv/、.runtime/、__pycache__/ 和 lesson-00-submission/。

请保持代码简单，说明入口、数据位置和启动方式。
完成后列出实际生成的文件、检查命令和仍需我在浏览器核对的事项。
不要替我填写实际运行结果或宣布我已通过验收。
```

生成后，在 VS Code 打开文件，核对位置与用途：

| 文件 | 你应能说明的作用 |
|---|---|
| `WORKBENCH_SPEC.md` | 你确认的第一版需求 |
| `app.py` | 启动服务、处理页面操作、读写事项数据 |
| `README.md` | 另一位同学怎样启动这版程序 |
| `.gitignore` | 哪些环境、运行数据和个人记录不进入 Git |

如果 Codex 只贴了一段代码，没有写入文件，告诉它在当前目录保存。如果生成了额外框架或依赖，要求它按已确认的标准库方案收回范围。

在项目根目录的终端运行语法检查。

**Windows PowerShell：**

```powershell
.\.venv\Scripts\python.exe -m py_compile app.py
$LASTEXITCODE
```

**macOS zsh：**

```zsh
.venv/bin/python -m py_compile app.py
echo $?
```

预期没有错误，退出码为 `0`。这只证明语法能解析，页面和保存能力还要由你现场检查。

**完成判断：**第一批源码在自己的目录里，语法检查通过，能找到程序入口与数据位置。

## 4. 启动，看到自己造出的工作台

**Windows PowerShell，项目根目录终端：**

```powershell
.\.venv\Scripts\python.exe -X utf8 app.py
```

**macOS zsh，项目根目录终端：**

```zsh
.venv/bin/python -X utf8 app.py
```

保持这个终端运行，在浏览器打开 `http://127.0.0.1:8001/`。应看到 V0.0 首页、“事项与决策”入口和空任务列表。终端暂时不返回输入提示，是因为服务正在运行。

若程序报错并退出，保存完整错误，让 Codex 先定位再修复，随后重新运行相同命令。页面打不开时，先确认程序是否仍在运行、终端是否报错、网址是否正确。

若提示端口被占用，保留错误，不结束其他人的进程。用自己系统的启动命令加上 `--port 8002`，再打开 `http://127.0.0.1:8002/`；后续检查全程使用同一个端口。

**完成判断：**你打开的是当前新项目启动的页面，能指出启动终端和程序文件。

## 5. 亲自走通四个检查

先登记自己的一件小事，逐项检查并记录实际结果：

| 检查 | 你的动作 | 通过条件 |
|---|---|---|
| 1. 新建与查询 | 输入真实标题、目标和完成条件，保存后打开任务 | 有任务编号，内容与输入一致，状态为“待处理” |
| 2. 空标题 | 只填空格，尝试新建 | 有明确错误；任务总数没有增加，原任务仍在 |
| 3. 结果与状态 | 完成自己的小事，填实际结果，再选择“已完成” | 再次打开能查到结果；状态与自己的选择一致 |
| 4. 重启恢复 | 在运行终端按 Ctrl+C（Mac 为 Control+C），用原命令重启并刷新页面 | 同一任务编号、内容、结果和状态都保留 |

发现失败就保留现象与原始错误，请 Codex 针对这一项修复，再重做受影响的检查。不要用“页面看起来正常”替代保存与重启检查，也不要清空数据库来掩盖失败。

检查完成后，让 Codex 只读指出“页面收到任务后如何保存”和“重启后从哪里读回”这两个结论的文件位置。你亲自打开 `app.py`，核对它给出的依据；不确定就记录“尚未确认”，再请它解释。

**完成判断：**四项检查来自你的实际操作，失败和修复均如实记录，两个程序行为有人工核验。

## 6. 留下基础版，后面逐讲优化

将[提交模板](../labs/L00/SUBMISSION.md)另存到自己项目的 `lesson-00-submission/L00-环境自检.md`，填写目录、环境、需求决定、生成文件、启动命令、四项检查和失败处理。模板可以从课程资料页面取得；获取文档不等于导入课程程序。

在终端运行两端通用命令 `git status --short`。新生成的源码还未跟踪时显示 `??`，属于正常状态；`.venv/` 和 `.runtime/` 应被忽略。若它们仍显示为未跟踪，先核对 `.gitignore`，不要把虚拟环境和运行数据库加入提交。

保留自己的完整项目目录和本机数据。交作业按开营入口提交源码、需求与个人记录，不附虚拟环境、运行数据库或凭据。再次启动时回到记录中的项目路径，继续使用自己的 `.venv`。

后面的能力应从这版实际成果逐讲增长：

| 后续阶段 | 基础版暴露的问题 | 优化方向 |
|---|---|---|
| L01 | 有记录，但“完成”是否有充分依据？ | 强化需求、可验证证据、任务关联与人工接受 |
| L02 | 换一次会话可能忘记约束 | 固化目录边界、禁止事项与完成要求 |
| L03 | 一段自然语言可能有多种解释 | 增加结构化需求和解析检查 |
| L04 | 手工把任务交给 Codex，改动过程缺少控制 | 补齐受控执行与最小复验，再首次交付 FlowERP |
| L05～L16 | 交付逐渐暴露质量、协作、运行与复用问题 | 逐步升级检查、协作、API、Web、反馈与交付能力 |

进入后续讲次时，带上自己的源码、需求和检查记录，先确认要补哪项能力，再修改。**基础版是继续建设的起点；后续升级要保留已有成果与失败记录。** 本文只规定 L00 的建设与验收，后续材料的起点和迁移操作需要与这版成果对齐。

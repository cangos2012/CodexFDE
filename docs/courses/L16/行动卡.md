# L16｜冷启动发布与工程答辩

**FDE 判断提示**：未预演需求服务谁、为什么现在做，原请求怎样收敛为此前未实现且可复验的小需求？执行前保留自己的理由，交接时用产品前后状态说明判断是否成立。详见[实践手册](实践操作手册.md)。

本讲综合检验 CLO-1～6。Codex 协助调查、实现与整理证据；学生确认范围和资源；同伴在同一候选上独立复验。FlowERP 必须产生此前未实现的可观察增量，工作台验证它能在新的问题与环境中持续组织交付。

先读[辅导资料](辅导资料.md)，再按[实践操作手册](实践操作手册.md)执行。

1. 记录版本、环境与实际隔离条件，由同伴按说明启动双系统。
2. 选择真实未实现的小需求，写清六段合同与允许写集。
3. 既有检查通过，新增检查因目标能力缺失而失败后，授权范围内实施。
4. 核对真实 Diff、独立 Eval、正常输入、失败打回及失败后状态。
5. 在同一候选完成具名复验，保存实际导出和有来源的反馈。
6. 验证恢复条件与数据，保留剩余风险，完成五分钟答辩及迁移解释。

本次只修改已确认需求涉及的文件，以及对应测试和必要说明。遇到写集不足，先明确新增原因和决定，不能把越界改动藏在格式化中。

初次判断、失败、修订、复验与同伴反馈都进入[提交模板](SUBMISSION.md)。演示审核不代替人的复验，参考案例不代替自己的新需求。

## 正式课程约定

- **核心内容**：容器化、健康检查、回滚意识、演示叙事和技术债说明。
- **演示结果**：从干净环境启动系统，展示一次成功任务、一次失败打回、一次结果导出和一次反馈写入。
- **课内增量**：完成结业检查表与五分钟答辩稿。
- **通过标准**：需求能生成 Spec 和代码；阻断级 Eval 全部通过；Loop 收敛或如实安全退出；Graph 审核结论可追踪；摘要和反馈能够正确生成；干净环境可启动且仓库无密钥。

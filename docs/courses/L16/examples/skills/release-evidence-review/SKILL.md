# 结业证据审查

读取用户提供的需求、候选版本、发布索引和实际记录。先列明可访问的证据范围，无法打开的材料标为未核验。此技能负责审查，不授予发布、数据恢复或具名审核权限。

分别判断以下链条，缺一项不以另一项替代：

- 冷启动：实际新环境、依赖、初始化、双服务与独立数据；旧卷重挂或换终端不算空状态重建。容器配置存在不算构建成功。
- 新需求：本次具体合同、新增验收实现前失败、既有基线通过、范围内修改和同一候选的新报告。未知用例、环境错误不算产品缺口。
- 失败：区分业务拒绝、网络故障和研发打回；核对失败后状态及原记录，修复不抹掉原失败。
- 人审：实际复验者、对象版本、操作和接受范围；演示账号、字段存在、Agent 自述不算独立验收。
- 发布与恢复：程序版本、配置和数据兼容；索引退出 0 不代表发布，备份存在不代表恢复正确。
- 反馈与复用：来源、场景、原话、决定和下一步；候选经验登记不代表后续事项已采用。

输出按“结论—证据位置—能证明的范围—缺口—下一步”组织，标为已证明、证据不足或与证据矛盾。优先指出会改变通过判断的问题；不按文件数量给分。保留用户授权和实际状态，不补写签名、退出码、耗时或线上效果。

核对命令成功时，进一步读取运行目录与具体轨迹。默认demo临时目录的反馈不能用另一默认库的summary回查；0条不能单独证明写入失败。Loop首轮converged且Token为0只说明起点已绿。Graph显示completed时仍检查审核策略，自动演示审批不成为真人决定。显式同目录回查到demo-day记录只证明演示记录可追溯；不要自动重跑demo，它会重置指定演示账本。实测对照见[五条命令与同目录反馈](../../五条命令与同目录反馈对照.md)。

用 [review-cases.md](references/review-cases.md) 检查自己的判断是否区分了常见反例。学生还需保存一次实际技能调用与人工复核，文件结构通过不代表审查质量已验证。

# 反例与预期判断

1. 新容器显示原订单，只有容器创建时间：不能证明空库冷启动，检查项目和卷及组织。
2. 健康成功，但工作台链接指向旧客户实例：单服务健康成立，交付关联错误。
3. 新增测试因模块缺失失败：环境失败，不能计为目标能力缺口。
4. 报告通过，候选后来又修改：原报告不能接受新候选，需重新复验。
5. demo-reviewer 已批准，学生没有同伴复验：属于演示审核，独立人审缺失。
6. 已备份，恢复后库存数量与原记录不符：恢复未通过业务核对，不能声明可恢复。
7. 保留旧失败和修订，独立复验者接受相同版本：可支持该候选的接受；没有发布与使用观察仍不能称线上效果达标。
8. 经验已登记，后续任务没有采用来源与版本：只有候选资产，复用闭环证据不足。

## 来自实际命令观察的反例

- 默认demo成功，默认summary为0条：先比较目录。实际默认演示临时目录与汇总目录不同，不能直接断言反馈写入失败。
- 显式同目录得到1条demo-day反馈：支持演示记录回查，不支持客户反馈或正式采纳。
- Loop首轮converged、tokens_used为0：本次没有修复，不能声称模型完成迭代。
- Graph的completed伴随“本地演示审批策略自动通过”：审核来源与真人接受的说法矛盾。

上述事实来自L16新环境观察；预期判断仍需与实际Skill回应分开保存，不宣称仅添加反例就已验证技能效果。

# L01｜以终为始：一次可验证的 AI 交付怎样完成？

## 第一次打开，按这条路线走

建成可记录任务与证据的个人工作台，再用它记录自身建设。

**开始前准备：** L00 环境自检记录。

| 顺序 | 打开什么 | 现在做什么，做到哪里再继续 |
|---|---|---|
| 1. 看懂本讲任务 | [辅导资料](辅导资料.md) | 先读开头的案例或总览，写下本讲要解决的问题；原理随实践回查 |
| 2. 开始操作 | [实践操作手册](实践操作手册.md) | 手册第 1～2 步：准备隔离区、确认自己的需求；自己的 Spec、范围与验收项已确认 |
| 3. 完成本人实现 | [实践操作手册](实践操作手册.md) | 第 3～7 步：先留红灯，再实现、复验并记录自举 |
| 4. 复验与交接 | [行动卡](行动卡.md)及手册末尾 | 第 8 步：整理个人记录、反馈与签收结论 |

**个人记录放哪里：** lesson-01-submission/；按手册“学习记录要求”逐项创建。报告、截图和教师示例用于对照；个人结论填写实际观察，尚未复验就注明待复验。

## 遇到问题，回到哪个入口

- 看不懂业务规则或判断理由：回到辅导资料的对应案例。
- 不知道在哪输入、缺少文件、命令报错或中途重开窗口：回到实践手册的准备、排错或恢复步骤，先确认原会话与候选。
- 不知道某个脚本能否直接运行：先查手册是否调用它；参考实验与个人交付按手册区分。
- 同一主题有多份 PPT、图或历史记录：按课堂指定版本使用；首次自学以当前辅导资料和实践手册为主。

下载或移动附件时保留本讲目录结构；只拷贝一个 Markdown 文件可能导致配图、Prompt 或脚本路径失效。

下面保留本讲已有说明，供查询实验机制、证据范围和课件记录。涉及历史实测、页数或同步状态的描述只对应原记录；当前学习顺序以上方导航为准。

**第一次来，先打开[辅导资料](./辅导资料.md)；准备动手时，打开[实践操作手册](./实践操作手册.md)。先用这两份，其余附件到对应步骤再打开。**

这一讲，你与 Codex 从“帮我搭建个人 AI 研发工作台”出发，做出一个能保存、查回任务与运行证据的命令行小工作台。你决定范围和验收标准，Codex 协助访谈、编写测试与实现，你亲自复验并判断是否接受。

整讲沿着一条线推进：**说清痛点 → 签署需求 → 测试发现能力缺失 → 实现工作台 → 复验 → 用新工作台记录自己的建设过程。** 最后一步叫“自举”。FlowERP 在 L04 才首次接入并交付，本讲先建 Workbench V0.1。

### 最后交什么，怎样算完成

个人记录统一放在隔离练习区的 `lesson-01-submission/`，文件清单和填写要求见手册的[学习记录要求](./实践操作手册.md#learning-records)。提交前核对四件事：

- **需求有依据**：自己的 Spec 能回指原始痛点、Codex 建议和本人决定，测试能对应验收项。
- **实现可验证**：五个操作可运行；保留实现前红灯、测试快照、范围内代码改动（Diff）和同一标准下的绿灯。
- **工作台确实用过**：能够查回自身建设证据；错误查询被拒绝后，原任务与记录保持完整。
- **本人能解释与迁移**：留下设计取舍、迁移答案、真实反馈和签收结论；反馈尚未取得就写“待复核”。

参考截图和示例结果用于理解目标，个人记录填写自己的实际观察。运行数据库留在本地，证据按课程指定渠道提供。

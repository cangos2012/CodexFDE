# L01｜怎样使用这组三阶段提示词

这组三阶段提示词配合[辅导资料](../辅导资料.md)和[实践操作手册](../实践操作手册.md)，带你从个人设计走到可运行的 Workbench V0.1。Codex 协助追问、测试、实现和解释；需求取舍、正式运行及最终决定由你完成。

## 先确认使用位置

按手册第 1 步创建隔离练习区，并让终端与 Codex 使用同一目录。在 `lesson-01-submission/` 留下原始问题、首次判断和个人设计。后续个人文件按手册文末[学习记录要求](../实践操作手册.md#learning-records)逐步建立，不需要从已删除的模板或行动卡复制。

选择当前阶段，将对应文件全文发送给 Codex，或附上文件并明确说“请执行这个阶段的提示词”。仅附文件时，它是供阅读的材料。提示词发到对话框；Codex 给出的终端命令才放进终端执行。

## 按当前阶段继续

| 阶段 | 对应手册 | 你与 Codex 要完成什么 | 交给下一阶段什么 |
|---|---|---|---|
| [1. 访谈并冻结范围](./01-访谈并冻结范围.md) | 第 1～2 步 | 从个人想法出发，明确使用过程、数据规则和验收；本人签署 | 自己的 Spec 版本、决定索引、未决项 |
| [2. 受控实现](./02-受控实现WorkbenchV01.md) | 第 3～4 步，第 5 步前交接 | 形成真实测试，亲自运行有效红灯，确认计划后实现 | 测试快照、红灯、授权范围、实际改动和诊断结果 |
| [3. 复验与自举](./03-复验并完成自举.md) | 第 5～8 步 | 亲自复验，导入建设记录，检查错误后的状态，解释并复核 | 真实红—Diff—绿链、自举记录、反馈、迁移和本人签收 |

每阶段可以有多轮对话，不是发三条消息就完成课程。已有决定和有效结果应接着使用；`00-handoff.md` 持续记录阶段状态，换会话时先读取它。

需求签署确认做什么，实现授权确认按什么计划修改，最终签收判断实际结果是否可以接受。相同计划已经明确授权后，Codex 应继续范围内工作；只有范围或标准改变才重新确认受影响事项。

## 对话中怎样配合

访谈时先说自己的判断，Codex 再帮助澄清。运行前先预测关键结果，运行后提供真实 `meta.json` 路径；不要只回“好了”。发现预测不符，先解释差异，再决定修复或修订。

提示词会在需要本人决定、正式运行或反馈时等待。你可以分次实践，不必在 30 分钟精讲内完成全部开发。继续时给出已有记录，避免反复初始化和重做同一个步骤。

| 遇到什么 | 从哪里继续 |
|---|---|
| 目录或环境不对 | 手册第 1 步及排错；保留已有结果 |
| 需求未定、教学参考未签署 | 交互 1，补齐本人决定 |
| 环境失败、零测试、起点已通过 | 交互 2，核对测试和起点；不人为制造红灯 |
| 实现或正式复验失败 | 原范围内修复，保留失败，重新采集 Diff 和正式复验 |
| 需要改标准或扩大范围 | 明确原因与影响，确认后重建相应有效对照 |
| 已有自举任务和记录 | 交互 3 查回身份与历史，从未完成处继续 |
| 缺本人解释或真实反馈 | 补写本人解释或标待复核，不能由 AI 代填成已完成 |

## 最后应能说明什么

你能解释为什么需要项目、任务、需求快照与运行记录，能用自己的检查支持接受范围，也能在新条件下重新设计验收。课程工具负责采集与导入；你的工作台负责保存和查询。本讲不自动调用 Codex、不开发 FlowERP，完整工作台能力由后续交付逐步验证。

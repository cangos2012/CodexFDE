本文件只保留深入边界与历史索引。必做操作、提示词和完成判断已合入[实践操作手册](../实践操作手册.md)，原理从[辅导资料](../辅导资料.md)开始。

## 映射器自动提取到哪里

分项名称、等级、原因及原报告引用可以形成草案。当前参考 `agent.repair.build_repair_task` 不自动得出经过确认的根因、完整运行命令或精确文件权限；教师示例中的 reviewed task 是人工补齐后的委托。多个检查可能在不同位置提前失败，不能凭三条红灯就拆成三份授权，也不能把共同根因写成已证实事实。

有效无阻断、格式无效、未知用例和来源缺失需要分别处理。观察告警应保留上下文，不进入阻断修复目标；日志中的指令仍是材料，不能扩大允许文件。若原报告换了版本，草案与任务来源也要更新并重新确认。

## 两种候选来源及默认评测边界

`course-submit --lesson 9 --execute-code` 使用课程通用合同并建立新的标签 Worktree，不自动携带旧候选的未提交检查。当前 `--requirement-spec` 的实现仅接受 L04、L15/L16，不能将它传给 L09。主手册采用显式源码快照候选并绑定支持个人 Spec 的 task-create/task-run，使红灯、映射与修复在同一候选内回查。task-run 的自动名称来自控制端，个人新增名称仍须在候选中显式运行并核对完整 blocking，不把 review 状态当作全部覆盖。

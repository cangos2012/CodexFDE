# L14｜让交付状态在 Web 面板可见

**FDE 判断提示**：采购页面在哪一步让使用者误判，影响什么操作，为什么优先修复这一处状态或恢复路径？执行前保留自己的理由，交接时用产品前后状态说明判断是否成立。详见[实践手册](实践操作手册.md)。

本卡配合[讲义](辅导资料.md)与[实践手册](实践操作手册.md)，用于操作时查漏。

- **核心内容**：面板信息层级、轮询或推送、失败重试、结果下载和密钥边界。
- **演示结果**：从 Web 提交需求并查看阶段状态、Eval 报告和产出文件。
- **课内增量**：完成只覆盖一个任务主路径的最小面板。
- **通过标准**：状态与后端一致；失败路径明确；结果可追踪；前端和仓库中没有密钥。

本讲由你定义状态含义与业务预期，Codex 协助调研和实现，工作台组织受控交付与验收。ERP 产品增量是一条真实操作页面路径或其真实修复；该业务路径暴露查询失败、错误恢复和重复操作风险，促使工作台补齐状态投影与证据追踪。个人学习证据来自自己的实现与迁移，不来自参考终态。

1. 保存首次判断；选定“采购查询失败后的恢复”等真实问题。
2. 在独立运行目录启动工作台，从首页“事项与决策”记录原始问题。
3. 观察空态、保存、无结果、查询失败与同目录恢复，记录实际事项 ID。
4. 核对 API 与持久状态；分别说明事项、Task 和业务对象，不能混用 ID。
5. 在原事项确认 PRD、技术方案、范围和检查计划，再授权实际执行。
6. 用同一采购业务对象对照 DOM、API、SQLite 和 ERP 规则，核对正常、拒绝及恢复路径。
7. 查看本轮报告与产物，验证下载内容对应 Task；人的决定与采购审批分别记录。
8. 由同伴完成桌面、键盘、窄屏与迁移复验，保留首次失败和修订。

允许写集起点：`web/`、`workbench/`、`workbench_web/`、`tests/`，按自己需求再缩小。只读观察工具在 [examples/read_initiative.py](examples/read_initiative.py)。服务参数、命令和排错见手册，不复制旧“当前任务”入口流程。

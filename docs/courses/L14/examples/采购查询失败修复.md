# 采购查询失败后隐藏旧结果并恢复同一单据

旧参考实验中，断网后点击采购“查询”，页面仍保留待审批单据和审批按钮，顶部还写着“数据已同步”。这会让使用者把历史结果当作当前可操作状态。原失败记录继续保留，本次在当前会话中修复页面并进行自动复验。

## 先用失败检查确认问题

新增检查先加载一张待审批采购单，再使查询失败，要求旧审批入口消失、原查询条件保留；恢复请求后，必须找回同一单据。另一检查让旧请求延迟返回，确认它不能覆盖较新请求的失败。修改前，两项检查都失败：旧结果和审批按钮仍可见。

## 修复怎样改变使用者的判断

采购查询现在统一经过页面加载流程，开始读取时清空旧采购与收货结果，显示加载状态。读取失败时显示明确原因与“恢复连接后点击查询或刷新”的操作提示；顶部同步状态同时说明失败。每次查询携带请求序号，较早返回的结果不再覆盖较新的判断。

原生截图｜本机隔离教学账套的实际断网操作。旧单据与审批入口已隐藏，搜索条件仍可使用。侧栏计数来自先前页面状态，不作为本次实时业务数量的证明。

隐藏旧结果没有删除采购单，也没有批准任何采购。恢复连接并查询后，同一采购单重新出现；实测随后经教学审批账号完成审批、收货过账，库存导出仍包含对应教学商品。业务权限和职责分离继续由后端检查。

## 本次验证及边界

两项新增检查与17项库存筛选检查通过；16项HTTP接口测试通过，29项阻断检查通过。浏览器实际观察了断网失败、恢复、收货和CSV下载。修改前测试输出、原截图和失败原因均保留。

本次代码修改由当前Codex会话执行，未通过工作台另建后台开发Task，也没有独立人审。它是实际修复与自动复验记录，不应被写成已经走完“事项授权—候选下载—具名接受”的交付链。学生仍需在自己的事项中组织相同判断，并补充键盘、窄屏和独立复验。

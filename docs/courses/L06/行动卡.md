# L06｜用 Harness 汇总证据和等级

现场问题：第三行商品无效，前两行却已经写入；分项检查报错，最终摘要仍显示通过。你要先恢复可信判决，再修复整批入口。

你确认整批规则与等级，Codex 协助修改自己的候选，复验者核对原检查和真实来源。产品增量是整批验证后才提交；工作台增量是统一执行 L05 原检查与新业务检查，保留等级、原因、耗时和退出码。

完整的 AI Harness 组织执行循环、工具、上下文和护栏，使模型提出的行动能在明确边界内执行并获得真实反馈。本讲建设的是其中负责质量检查的 Eval Harness；Codex 的内部运行、课程工作台的事项组织和本讲检查运行器，需要分层理解。

FDE 贯穿本次工作：从运营的整批要求作出现场判断，借助 Harness 完成受控交付，再把经确认的经验和流程送回后续任务。现场问题决定需要什么控制，运行失败推动规则与能力修订；业务取舍、独立复验与接受决定由人承担。

1. 辅导资料第 1 节，用商品导入解释 Harness 四组职责和一次行动的交接；区分完整概念、本讲实现与后续建设，并说明 FDE 三个循环如何相互反馈。
2. 按手册第 1～3 节建立会话，保留自己的首次判断、原始合同失败与假绿灯。
3. 第 4 节只修汇总器，证明报告可信但业务仍阻断。
4. 第 5 节只修整批入口，让原检查通过；第 6 节换七行并拒绝旧报告。
5. 第 7 节查看两处差异，交给复验者；未完成具名复验时如实记录待办。
6. 在个人证据索引中设计一次向采购导入的迁移，写明经验来源、适用条件、流程版本及复用失败的处理；尚未执行的后续事项标为设计示例。

核心内容：用例发现、统一退出码、阻断级与观察级指标、机器可读报告。

演示结果：Harness 输出分项结果、阻断结论和 JSON 报告。

课内增量：实现最小 Harness，将第 5 讲用例纳入统一执行。

通过标准：阻断用例失败时返回非零退出码；观察项失败只记录告警；报告保留运行时间和失败原因。

评价证据是自己的判断、差异、原检查红绿结果、七行迁移与独立意见。参考运行不替代个人完成。实际命令统一从[操作手册](实践操作手册.md)开始。

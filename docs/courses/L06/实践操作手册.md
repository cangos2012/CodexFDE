# L06｜实践操作手册：统一库存口径与可信汇总

> **终端选择：**本手册同时提供 Windows PowerShell 与 macOS 默认终端 zsh 的操作。每一步只运行自己系统对应的代码块；标为“通用”的 Python、Git 命令两端相同。开始或重开终端时，先按[macOS 环境与路径约定](../../reference/实操手册执行与排错.md#macos-zsh)恢复本讲使用的虚拟环境，再核对当前源码位置。

未分系统的终端代码块中，`python`、`git` 和 `codex` 命令两端通用；先激活当前步骤指定项目的 `.venv`，再逐条执行。自然语言提示词复制到 Codex 对话，不能粘到终端。

本讲沿同一候选完成：看查询 5、导出 8 的矛盾 → 先修汇总 → 再修导出 → 换数值复验 → 交接给 L07。商品导入现在是[选读实验](商品导入实验手册.md)，不要混用两套 session。

## 1｜准备自己的来源与候选

在控制仓库根目录的终端中执行。先找到自己 L05 的 `session.json`，对应 run 必须有 `submission.json` 和 `frozen-checks.json`，原候选仍然存在。缺少时回 L05 补齐，不能用参考记录伪装个人来源。

**Windows（PowerShell）：**

```powershell
$python = (Resolve-Path '.venv/Scripts/python.exe').Path
$tool = (Resolve-Path 'docs/courses/L06/examples/stock_practice.py').Path
$l05Session = Read-Host '粘贴自己的 L05 session.json 完整路径'
$run = Join-Path (Get-Location) ('.runtime/l06-stock/' + [guid]::NewGuid().ToString('N'))
& $python -B -X utf8 $tool prepare --run $run --l05-session $l05Session
if ($LASTEXITCODE -ne 0) { throw '准备失败，先读错误；不要继续' }
$session = Join-Path $run 'session.json'
$candidate = (Get-Content $session -Raw -Encoding UTF8 | ConvertFrom-Json).candidate
$reports = Join-Path $run 'reports'
```

**macOS（zsh）：**

```zsh
prepare_l06_stock() {
  python="$PWD/.venv/bin/python"
  tool="$PWD/docs/courses/L06/examples/stock_practice.py"
  printf '粘贴自己的 L05 session.json 完整路径（不加引号）：\n'
  read -r l05Session || return 1
  run="$PWD/.runtime/l06-stock/$("$python" -c 'import uuid; print(uuid.uuid4().hex)')"
  "$python" -B -X utf8 "$tool" prepare --run "$run" --l05-session "$l05Session" || return 1
  session="$run/session.json"
  candidate="$("$python" -X utf8 -c 'import json,sys; from pathlib import Path; print(json.loads(Path(sys.argv[1]).read_text(encoding="utf-8-sig"))["candidate"])' "$session")" || return 1
  reports="$run/reports"
  printf '会话：%s\n只修改候选：%s\n' "$session" "$candidate"
}
prepare_l06_stock
```

准备程序复制源码到新的隔离目录，记录两仓来源与哈希，复制个人 L05 三个原文件，植入 CSV 错用在库字段和运行器漏算阻断失败两个教学缺陷。它不修改控制仓库或客户仓库，也不代表学生已经完成实现。现有预占服务是建立库存状态的支架；本讲不要求提前实现 L07、L08 功能。

允许修复的文件只有 `eval/l06_runner.py`、`flowerp/service.py`。L05 原检查、`eval/l06_checks.py`、`tests/test_l06_runner.py` 等其余文件冻结。

## 2｜留下首次判断，建立命令入口

在个人[提交记录](SUBMISSION.md)写：8−3 为什么是 5；再请求 6 时应发生什么；分项失败而汇总通过时先改哪里。

在同一个窗口定义下面的调用函数。它会核对真实退出码，报告和命令回执保存在候选外，已有报告不能覆盖。

**Windows（PowerShell）：**

```powershell
function Invoke-L06Stock {
    param([string]$Action, [string]$Name, [int]$Expected, [int]$Opening=8, [int]$Reserved=3)
    $report = Join-Path $reports ($Name + '.json')
    $arguments = @('-B','-X','utf8',$tool,$Action,'--session',$session,'--report',$report)
    if ($Action -eq 'run') { $arguments += @('--opening',"$Opening",'--reserved',"$Reserved") }
    & $python @arguments
    $actual = $LASTEXITCODE
    if ($actual -ne $Expected) { throw "预期退出 $Expected，实际 $actual；先查本次回执" }
}
```

**macOS（zsh）：**

```zsh
invoke_l06_stock() {
  local action="$1" name="$2" expected="$3" opening="${4:-8}" reserved="${5:-3}"
  local report="$reports/$name.json" actual
  local -a arguments
  arguments=(-B -X utf8 "$tool" "$action" --session "$session" --report "$report")
  if [ "$action" = run ]; then
    arguments+=(--opening "$opening" --reserved "$reserved")
  fi
  if "$python" "${arguments[@]}"; then actual=0; else actual=$?; fi
  if [ "$actual" -ne "$expected" ]; then
    printf '预期退出 %s，实际 %s；先查本次回执。\n' "$expected" "$actual"
    return 1
  fi
}
```

## 3｜观察原始失败与假绿

**Windows（PowerShell）：**

```powershell
Invoke-L06Stock contract '01-contract-red' 1
Invoke-L06Stock run '02-false-green' 0
Invoke-L06Stock review '02-false-green' 1
```

**macOS（zsh）：**

```zsh
invoke_l06_stock contract '01-contract-red' 1 &&
invoke_l06_stock run '02-false-green' 0 &&
invoke_l06_stock review '02-false-green' 1
```

打开 `02-false-green.json`：必须有四项登记，库存项实际为失败，原因应定位查询 5、CSV 8；总判决却 pass。review 应拒绝这一矛盾。模块不存在或数据库打不开不属于这条业务反例，要先修环境。

## 4｜只修汇总器

给 Codex 当前 `$candidate` 的完整路径，让它仅修 `eval/l06_runner.py` 的阻断汇总。原检查、等级、异常信息和库存服务保持不变。

**Windows（PowerShell）：**

```powershell
Invoke-L06Stock contract '03-contract-green' 0
Invoke-L06Stock run '04-business-block' 1
Invoke-L06Stock review '04-business-block' 0
```

**macOS（zsh）：**

```zsh
invoke_l06_stock contract '03-contract-green' 0 &&
invoke_l06_stock run '04-business-block' 1 &&
invoke_l06_stock review '04-business-block' 0
```

九项合同应全过；业务仍有一个阻断失败、一个观察告警，总判决 block。review 通过只证明红报告如实对应当前来源，不表示业务已通过。

## 7｜独立复验，再接入下一讲

将 session、两处实际差异、红绿报告及回执交给复验者。复验者使用新报告名，例如 `08-peer-stock`，执行相同 run、review 和 contract，不让 Codex 在复验过程中继续改代码。个人记录填写实际复验者、时间、结论和未覆盖风险，并关联工作台原事项。参考仓库运行结果不能替代个人完成。

接下来按[检查接入手册](../L07/L06检查接入手册.md)，把已验证的检查接入独立 L07 候选。接入前记录该阶段的新基线和写入范围，不能把它算进 L06 的两个修复文件。工作台的人审及课程提交按真实任务状态完成，不能只凭本地脚本通过填写 accepted。

## 8｜中断恢复与失败处理

重开窗口后，先回控制仓库根目录，重新设置 `$python`、`$tool`，把 `$session` 设为此前完整路径，从中读取 run、candidate，恢复 reports，再复制第 2 节函数。不重新 prepare，不覆盖旧报告。

**Windows（PowerShell）：**

```powershell
$python = (Resolve-Path '.venv/Scripts/python.exe').Path
$tool = (Resolve-Path 'docs/courses/L06/examples/stock_practice.py').Path
$session = Read-Host '粘贴本讲原 session.json 完整路径'
$meta = Get-Content -LiteralPath $session -Raw -Encoding UTF8 | ConvertFrom-Json
$run = $meta.run
$candidate = $meta.candidate
$reports = Join-Path $run 'reports'
```

**macOS（zsh）：**

```zsh
resume_l06_stock() {
  python="$PWD/.venv/bin/python"
  tool="$PWD/docs/courses/L06/examples/stock_practice.py"
  printf '粘贴本讲原 session.json 完整路径（不加引号）：\n'
  read -r session || return 1
  run="$("$python" -X utf8 -c 'import json,sys; from pathlib import Path; print(json.loads(Path(sys.argv[1]).read_text(encoding="utf-8-sig"))["run"])' "$session")" || return 1
  candidate="$("$python" -X utf8 -c 'import json,sys; from pathlib import Path; print(json.loads(Path(sys.argv[1]).read_text(encoding="utf-8-sig"))["candidate"])' "$session")" || return 1
  reports="$run/reports"
  printf '会话：%s\n候选：%s\n' "$session" "$candidate"
}
resume_l06_stock
```

- 冻结文件变化：核对差异并恢复原检查，再用新报告名运行。
- 找不到客户源码：按项目登记或 `FLOWERP_PROJECT_ROOT` 配置独立 FlowERP；不在控制仓库创建重复业务包。
- 准备时找不到 CSV 字段：源码结构已变化，先核对适配，不猜测替换。
- 行为已正确但测试仍红：读实际失败对象；合同失败修运行器，业务失败查具体状态，来源失败重新运行当前候选。

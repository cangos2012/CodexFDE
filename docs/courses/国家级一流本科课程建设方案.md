## 学情、主线与最终成果

面向零基础或少量编程经验学员，先诊断文件操作、命令执行、业务判断和结果解释的起点。当前 L00 从没有源码的空目录建设基础工作台 V0.0，先做 Python 与 SQLite 标准库自检，再由学生确认需求、监督 Codex 生成代码并亲自检查新建、查询、结果保存与重启恢复。安装成功仅证明工具准备，V0.0 能运行也不替代后续受控交付能力的建设。记录“可独立／需提示／尚未达成”，受阻者先补练。

全课程沿同一条主线：用 Codex 搭建个人 AI 研发工作台，通过工作台组织人与 AI 协同，持续开发独立的 FlowERP。L01～L03 由学生直接监督 Codex 建立规则、Spec 与解析能力；L04 先接受工作台 V0，再首次组织库存导出；L05～L15 从客户问题推动工作台能力增长并复验产品；L16 由陌生环境接手，现场完成此前未实现的小需求。

最终成果包含可复用的工作台、通过它持续交付的客户产品，以及学生自己的判断与迁移证据。FDE 的现场、交付、能力三循环通过真实任务关联；工作流复用须保留来源、版本、适用边界、复验与具名审核，不能表述为模型自动进化。

## 混合式教学与分层支架

线上精讲原则上不超过 30 分钟，负责现场问题、必要概念与关键示范；线下或课后完成真实构造、失败实验、同伴反证、修订和等价任务迁移。当前蓝图安排是教学设计，实际课时须试讲校准，不能当作学校核定学时。PPT 的实际内容、版本和逐页验收按蓝图的本地课件检查执行，不以固定页数代替教学质量。

材料按“目标 → 操作位置与动作 → 预期结果 → 失败处理 → 完成判断 → 迁移任务”组织。零基础学生提供空白模板、逐步提示与错误解释；有经验学生减少提示、增加反例与迁移。相同业务规则和证据真实性不降级，挑战来自判断和解释，不来自术语或代码量。

## 形成性评价、责任与证据保存

工程验收与学生学习分别记录。工程检查约定、实际实现、范围内 Diff、同版本复验与具名人审；学生评价检查本人能否预测结果、解释失败、识别越界并迁移。原先已正确时如实记录，不制造红灯；参考实现、自动测试通过和教学人物故事都不能替代学生自己的证据。工程任务允许按授权使用 Codex，短时独立解释须保留本人回答；评分权重和达成阈值待课程团队与校方审定。

保留首次判断、原始失败、修订前后版本、反馈、提示级别和独立检查结果，并以任务身份、来源和版本关联。按学校授权范围保存学习记录；仓库不包含学生敏感信息、未经授权作品、凭据、运行数据库或运行报告。教学夹具须标为软件验证材料，不计作真实学习成效。

工程诚信、数据安全与协作责任落在实际决定中：拒绝伪造成功，采购批准与执行分离，工作台和客户数据库分开，独立复验者依据当前证据作决定。工作台 Eval 与 ERP 业务 Eval 分别验证，两者不能互相替代，参考代码也不替代学生建设。

## 持续改进

真实开课后按 CLO 统计可独立、需提示、尚未达成的人数及分母，比较首次与修订后提交、不同起点学生的变化和主要误区。每轮形成“问题证据 → 原因假设 → 教学调整 → 下一轮等价任务验证”，由教师审核后同步合同、讲义、实践与课件。满意度和平均分只作辅助。

当前真实教学数据、教学周期、同行评价与改进效果均待真实教学采集；学校课程身份、团队审核及申报资格待校方确认。本文恢复的是建设设计，不能据此填写“已达成”“符合申报条件”或认定结果。
